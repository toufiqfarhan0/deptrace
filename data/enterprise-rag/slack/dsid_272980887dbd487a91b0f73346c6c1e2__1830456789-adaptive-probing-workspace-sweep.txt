olivia: nice. how does the probe pick sizes?

alex: short version: run tiny microbenchmarks across candidate workspace sizes and kernel variants (FlashAttention, Triton-attn, cuBLASLt fallback). We score candidates by latency + alpha*mem and pick smallest that meets success criteria (no OOM) under a short warm+meas loop. Pseudocode: 
```
for cfg in candidates:
  try:
    run_kernel(cfg, warm_iters=3, meas_iters=10)
  except OOM:
    mark_bad(cfg)
score = latency + alpha * mem
choose argmin(score)
```
We also add a penalty for any cfg that triggers allocator fragmentation events.

jen: is this per-model or global?

alex: per model+dtype+device_family. We cache chosen workspace in mempool metadata with TTL=6h. Also re-probe if observed seq distribution shifts: if >20% of recent requests fall outside the probed seq range we re-run a lightweight probe.

tao: KV cache changes footprint a lot for long chat sessions — how do you account for that?

alex: probe includes KV footprint estimate: avg_kv_bytes(seq_len, batch). We simulate KV occupancy by reserving a kv_bytes estimate when running microbench so the kernel allocator sees realistic free memory. Also we reuse pinned KV buffers in the pool rather than freeing them between calls; this reduced transient OOMs in the sweep. We adjusted the mempool slab allocator to allow small kv-only reservations so they don't evict workspace slabs.

maria: any regressions or flakes surfaced by probe?

alex: one notable regression: cuBLASLt GEMM kernel choice for small seq (<128) ended up slower due to tiling mismatch when we switched priority to memory-efficient kernels. For those small seqs we now force cuBLAS (not cuBLASLt) until we can tune the tiling heuristics in the kernel chooser.

olivia: what about batching heuristics interacting with probe? e.g., continuous batching that increases seq variance at runtime

alex: good point — probe assumes a target batching policy. We added a lightweight runtime hook: if observed batch*seq variance exceeds threshold, we stop accepting probed choices for new tasks and fall back to conservative static workspace that tolerates high variance. Also added metrics: probe_success_rate, probe_latency_ms, chosen_workspace_bytes to dashboards.
