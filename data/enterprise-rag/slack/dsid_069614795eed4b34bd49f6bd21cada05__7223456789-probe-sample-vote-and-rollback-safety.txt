noah: recap from today's incident: we had 30s of EU network tail that led to ~120 tenant migrations in 2m. main pain was cold-KV and a handful of hard-residency tenants bouncing unexpectedly. want to propose a probe-sample + voting model before promoting a region.

meera: sounds good. can you outline the voting model?

noah: idea: when local p95 crosses threshold, instead of immediate swap we 1) schedule lightweight workload-probes (kv lookup + small model inference) to candidate regions, 2) sample N proxies (not all) to avoid thundering, 3) compute a vote across probes + local metrics over window W, and 4) require majority+margin to promote. also honor residency stamp which can veto cross-border promotions.

ako: important: probes must be non-PII and mirror typical request shape. also sampling strategy should prioritize tenants with recent swaps. we should avoid probing every tenant to save cost.

meera: agree. propose probe_config:
```
probe_sample_pct: 5            # percent of proxies for tenant
probe_types: ["kv","model-lite"]
window_sec: 20
vote_margin_pts: 10
min_votes: 3
max_probes_per_minute: 1000
```

noah: residency veto: if x-residency is hard -> veto unless emergency_override. soft -> treat as vote penalty (e.g., -delta). veto must be surfaced in audit logs.

ops-bot: deployment note: probe-vote v0.1 -> staged canary: 2025-07-22T06:00Z.

ako: two more pieces: 1) rollback safety net: after promote, monitor for 30s; if post-promote tail increases beyond threshold, automatically roll back to previous region with a higher cooldown and mark tenant as "unstable" for longer. 2) prewarm ticketing: if promotion pending, enqueue prewarm and block promotion until a minimal prewarm success ratio achieved unless emergency_override.

meera: rollback auto is risky. needs operator config: auto_rollback_enabled=true|false and a clear window/threshold. also ensure rollback emits high-sev alert and creates a paged incident if instability persists.

noah: agreed. default disable auto-rollback for hard-residency tenants. config sketch:
```
promote_policy:
  use_probe_vote: true
  probe_window_sec: 20
  vote_margin_pts: 12
  min_votes: 3
  residency_veto: true
  auto_rollback_enabled: true
  rollback_window_sec: 30
  rollback_threshold_pct: 15  # post-promote p95 increase pct to trigger rollback
  post_rollback_cooldown_sec: 600
```

ako: where to keep per-tenant unstable state? control-plane DB with a short-lived cache in proxies. mark tenants as unstable with reason tags: PREWARM_FAIL, ROLLBACK_HIT, RESIDENCY_BLOCK, EMERGENCY_OVERRIDE. proxies consult cached unstable flag to avoid repeated immediate swaps.

meera: security: sec-bot, prewarm/probe traffic touches only anonymized keys and returns non-PII metrics. also probes must not cause cross-border model state writes.

sec-bot: noted. will require probe payload audit and whitelist for allowed endpoints. also mandate encryption of probe headers and hash-only consent-stamp in logs.

noah: tests: unit test voting math, integration: simulate 1k tenants with mixed residency, chaos: transient p95 blips vs real node loss, E2E: canary migrate 50 tenants with prewarm to measure SLO impact.
