Alex: quick RFC follow-up — private egress segmentation. We need to pick a long-term pattern: per-tenant private endpoints (static ENIs / IPs) vs shared regional egress pools with SNAT. Tradeoffs?
Mira: per-tenant endpoints wins for isolation and compliance. downside is ENI/cert management and per-tenant networking churn.
Sam: ENI limits are real at scale. 1k+ tenants -> hundreds of ENIs per region. Also bursty autoscaling makes IPs hard to predict.
Jonathan: hybrid idea: reserved per-tenant pools for enterprise customers that require static IPs, and shared pools for self-serve. Route priority + fallback to shared pool if reserved is exhausted.
Alex: agree hybrid seems pragmatic. Key questions: how do we preserve source IP for things that require it (webhooks, allowlists)? static ENI only? or proxy that preserves customer identity?
Mira: for strict src-ip requirements customers need static IPs. We can offer them a per-tenant pool (ENI/NAT) or a tenant-side proxy that carries a stable header, but some customers won't accept header-based auth.
Sam: operational cost: per-tenant ENI adds monthly cost + more NAT instances. Also limits on ENIs per instance type. Could we use AWS Network Load Balancer + TLS passthrough and proxy protocol to preserve src? ops complexity increases.
Jonathan: alternative: use eBPF on edge nodes to do 1:1 NAT mapping and advertise per-tenant VIPs. Means fewer ENIs but more infra complexity and richer dataplane code.
Alex: what about control plane responsibilities? If we separate CP from dataplane (private), the CP shouldn't be doing per-packet decisions. CP's job = routes, policies, certs. Dataplane should own IP life-cycle and NAT state.
Mira: +1. Keep CP minimal: allocation decisions, policy -> push to dataplane agents. Agents handle ENI attach/detach and cert renewal.
Sam: fallback semantics need to be explicit in config and rollouts: e.g. `egress_policy: hybrid; priority: tenant; fallback: shared; preserve_src: true|false` — we need a single source of truth so routing isn't ambiguous.
Jonathan: agreed. Also need SLOs for fallback: how long to keep trying tenant pool before failing to shared? and observability: tag requests with which pool served them for billing and debug.
Alex: security: shared pool must be strongly isolated at L7 and audited. Any cross-tenant leakage would be catastrophic.
Mira: TLS termination decision: for private endpoints we should prefer TLS passthrough to customer endpoints to avoid handling customer certs; for shared egress we may terminate TLS for observability but must be opt-in.
Sam: cost model: produce a simple bucketed pricing estimate for per-tenant static IP vs shared (per-GB egress). We'll surface that in RFC so product can price it.
