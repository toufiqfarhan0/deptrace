vik: ah there's the tradeoff — aggressive latency targets -> small batches -> slow background prefetch. That explains slow KV warming. How did the replay harness compare?

janet: I ran both synthetic onramp and replay of production traffic (same qps profile). Replay warmed prefixes in ~60s; synthetic warmed in ~180s. Root cause: replay has request locality and prefixes are long-lived, synthetic used randomized prefixes.

leo: So apples-to-apples requires synthetic to use same prefix distribution as replay. But in real-world surges you may get novel prefixes (e.g., new chat contexts) so synthetic with randomized prefixes is a valid worst-case.

janet: True. We're concerned about simultaneous kernel fallback on new node causing KV eviction churn. When the allocator OOMs and kernel falls back, it temporarily disables certain KV prefetch paths. Sequence: node join -> small batches -> many unique prefixes -> allocator pressure -> kernel fallback -> warming stalls -> cache miss spike -> higher tail latency.
