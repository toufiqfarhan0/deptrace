elena: Hey, heads up — found a reproducible hang in the Python SDK when you close the Client while consuming a streaming response with `async for`. Minimal repro below, happens on 0.8.x branch :(
elena: repro:
```py
async def sample():
    client = AsyncRedwoodClient(...)
    stream = await client.generate_stream("hi")
    async for chunk in stream:
        print(chunk)
    # simulate shutdown during iteration
    await client.close()
```
When `client.close()` runs while the underlying httpx response reader is mid-iteration, the background reader task sometimes never finishes and the process hangs on exit.
jordan: hmm, do you see any pending background tasks in the logs or an exception? :thinking:
elena: I see an asyncio.Task still alive in the shutdown log and event loop won't stop. No exception, just stuck on `await response.aread()` in the background reader. Stacktrace points to httpx internals, but our wrapper is probably not cancelling the reader task in the right order.

elena: stack:

env: python 3.11, httpx 0.24.0, anyio 4.0.0, py-sdk 0.8.4-rc
jordan: I vaguely remember we rely on a background `stream._reader_task` that reads chunks and puts them onto an asyncio.Queue. If `client.close()` closes the httpx transport first, the reader awaits forever on the queue put, or vice versa. Ordering bug.
elena: exact. quick workaround that unblocks tests: call `await stream.aclose()` before `await client.close()` or use the client as an async context manager:

```py
async with AsyncRedwoodClient(...) as client:
    async for chunk in await client.generate_stream(...):
        pass
# context manager ensures stream cleanup first
```
