jess: Hey team — saw a weird failure in the Python starter sample when streaming a fncall response in json_mode + schema_strict. The streaming chunks are fine, but on retry after an auth refresh the schema validator rejects the reassembled payload. Repro and logs below. cc @priya

ryan: Interesting. Is the validator running on the client or server side?

jess: Client-side. We run incremental schema validation as chunks arrive (to show partial structured preview). When a 401 happens mid-stream, the SDK triggers a token refresh and retries the request. The retry path reconstructs the structured output by concatenating chunk strings, but we noticed the retry was re-encoding already-validated chunks which adds quoting around nested JSON pieces, so final JSON fails strict schema checks.

priya: Can you paste the simplified trace & payload?

jess: Simplified trace:
```
1) start streaming fncall -> client receives chunks: '{"tool":"search","args":{"q":"redwood"', '}}'  (chunks are raw strings representing partial JSON parts)
2) midway -> 401 from server (expired token)
3) SDK refreshes token, retries
4) retry reconstructs payload using `''.join(chunks)` but also runs `json.dumps` on the reconstruction -> final string becomes '"{...}"' (string wrapped)
5) client schema-strict validator raises: 'TypeError: expected object at root, got string'
```

qa-bot: Failing test: devex/py-sdk-stream-tests::test_stream_retry_schema_strict — opened issue DEVEX-4399

ryan: So two orthogonal problems: a) retry path is double-encoding assembled stream, b) incremental validator needs to accept pre-parsed objects or at least detect that input is already a JSON string wrapper.

priya: Proposal: change retry reconstruction to join raw chunk bytes and call json.loads only once (never json.dumps). Also add a guard in the validator: if top-level type is string, attempt json.loads to recover; if that still fails, raise a user-friendly error suggesting `SDK_JSON_MODE` or `schema_strict` configs.

jess: +1. Also add e2e that simulates token expiry mid-stream (use test server that returns 401 on Nth chunk) so CI will catch regressions.

ryan: For an immediate customer workaround, tell them to disable schema_strict in starter kit (temporary) or set `client_config.stream_retries = false`. Add a clear notice in CHANGELOG.

priya: I'll draft the PR: fixes in python sdk stream retry handler, add unit + e2e, and improve error message to include suggestion: 'If you are using json_mode with schema_strict, ensure your retry serializer does not wrap already-serialized JSON.'
