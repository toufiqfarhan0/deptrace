Luca: Key constraints: we still need enough context to debug latency/trace issues. Totally removing all identifiers will make some incident triage harder. Suggestion: deterministic hashing for identifiers that preserves uniqueness but hides the literal value, plus optional reversible encryption for a small TTL backed by KMS for security team/audit use.

Priya: From a privacy/compliance angle, hashing helps but can still be considered PII if it's reversible or linkable. Need a clear data access policy & audit logs. If we keep reversible keys, restrict to a narrow role and log every access. Also retention windows must be short for raw spans with PII.

Jin: Proposed tech approach: add an OpenTelemetry Span Processor that sanitizes span attributes before export. Rule engine: allow-list safe attributes, redact or hash patterns matching emails/phones/SSNs. For sensitive downstreams (external vendors) we should encrypt the whole payload with envelope encryption. We can configure per-exporter behavior. Example config (rough):
```yaml
processors:
  pii_redactor:
    rules:
      - match: ".*email.*"
        action: hash
      - match: ".*phone.*"
        action: redact
exporters:
  otlp/inhouse:
    endpoint: kafka://raw-telemetry
  otlp/securestore:
    endpoint: s3://secure-telemetry
    encrypt_with_kms: true
service:
  pipelines:
    traces:
      processors: [pii_redactor]
      exporters: [otlp/inhouse, otlp/securestore]
```

Maya: That looks doable. A couple Qs: 1) deterministic hash algorithm (sha256 with HMAC salt) or something reversible? 2) How do we prevent downstream analytic indexes/search from rehydrating hashed values into PII?

Luca: For (1) HMAC-SHA256 with a per-environment salt stored in KMS is a good compromise — not reversible without the key, deterministic for joins. For truly sensitive tenants we can do envelope encryption of the full span. For (2) enforce exporter-level transforms: the pipeline that writes to ES or BigQuery should strip or hash before indexing. Also ensure ingestion paths (ad-hoc consumer jobs) pull from secure streams only if they have auth + approval.

Priya: Additions: update our Data Processing Agreement docs and the internal security checklist. We should also add a periodic audit job that samples a subset of exports to ensure no PII is escaping. Logs of who unwrapped KMS keys must be stored in the audit trail (immutable).
