samir: proposed short-term mitigations: 1) quota_engine: ignore provisional deltas that originate from a different sample_epoch than the session's active epoch for enforcement decisions (still show them in UI), 2) add a tiny hysteresis window (2-5s) before provisional-driven route-level enforcement for sessions that had a price_hint change.
grace: alternatives? we could also derive a conservative provisional_cost for enforcement by re-evaluating all sampled tokens with min_price_seen_in_epoch to avoid false positives. That could under-enforce though.
leo: argue for hysteresis + epoch isolation. preserves strict enforcement for steady-state traffic but prevents mid-request churn from instantly tripping routes. We already have sample_epoch propagated from router for canary/fallback flows.
kat: implementation sketch for quota calc (pseudo):
```
quota_bucket = sum(tokens where sample_epoch == session.active_epoch)
if epoch_changed_within_last_5s(session):
  use_hysteresis = true
if use_hysteresis:
  allow_soft_buffer = min(0.5 * route_threshold, 50_usd_equiv)
  enforce_if(prior_provisional + quota_bucket > route_threshold + allow_soft_buffer)
else:
  enforce_if(prior_provisional + quota_bucket > route_threshold)
```
