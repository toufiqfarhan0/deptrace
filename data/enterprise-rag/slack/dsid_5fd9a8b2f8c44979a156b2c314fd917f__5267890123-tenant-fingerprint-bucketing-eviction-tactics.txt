devon: How are you fingerprinting? any PII risk?

sree: We normalize by lowercasing, stripping punctuation, canonicalizing whitespace, removing email-like tokens and 12+ digit numeric tokens, and replacing UUID-like tokens with <ID>. Also drop assistant-only system tokens before hashing. Example function:

```py
def fingerprint(prefix):
    s = prefix.lower()
    s = EMAIL_RE.sub('<EMAIL>', s)
    s = UUID_RE.sub('<ID>', s)
    s = NUM_RE.sub('<NUM>', s)
    s = PUNCT_RE.sub('', s)
    s = ' '.join(s.split())
    return sha1(s.encode()).hexdigest()[:16]
```

We keep the raw prefix out of the key to avoid leaking full user text, only store fp. That reduces distinct key cardinality and increases reuse.

jon: Sounds good but collision domain? shortened hash to 16 hex chars is ~64 bits — cheap but collisions possible. Did you add tenant salt?

sree: Yes: key template is: `tenant:{tenant_id}:v2:fp:{fp}:lenb:{len_bucket}`. We include tenant_id so different customers don't mix. Also we bucket length (len_bucket) into bins (0-64,65-256,257-1024,>1024) so very similar-length prompts map together.

maria: What about TTL bucketing? you mentioned that.

sree: Instead of arbitrary TTL per request we quantize to 3 buckets: short (8s), medium (60s), long (300s). This reduces fragmentation because previously TTLs were noisy and produced many near-unique residency timers causing premature evictions. After quantization median residency increased ~22%.

devon: Any regressions on quality? are we over-sharing across paraphrases and accidentally serving wrong context?

sree: We audited a sample of 10k requests from canary tenants — false reuse (where reused KV produced incorrect tokens) < 0.02%. Most were near-duplicates or trivial paraphrases where reuse is fine. Still, we added a safety check: when fp match but prompt token overlap < 30% we skip reuse.

jon: How about eviction policy? LRU was thrashing earlier with longctx streams. Did you change policy?

sree: We kept LRU but added adaptive clock-like backoff for long-lived sessions: entries pinned briefly if they appear in >3 consecutive requests from same session id, which reduces eviction of hot longctx slices. Pin window decays exponentially to avoid long-term leaks. That plus TTL buckets reduced churn.
