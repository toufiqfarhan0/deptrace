marta: Proposal: introduce a compact "checkpoint" token header so the edge can offer a best-effort resume for streaming requests without full KV-cache sync. Token is opaque to clients but encodes a tiny session handle.

idea: edge replies include `X-Edge-CP: <token>` for active streams. If client reconnects and supplies token, edge will try a soft-resume and continue from the last emitted index when safe.

sam: I like the ergonomics but worried about semantics. If the original stream triggered side-effects we must not silently replay.

marta: Agreed. Resume only for explicitly idempotent or read-only endpoints (embeddings, logs, read-only chat). For non-idempotent endpoints we either refuse resume (409) or expose a safe replay mode (read-only) that never re-applies side-effects. We'll make this explicit in the API docs.

jade: Storage cost? holding millions of short TTL tokens could add up.

marta: Token payload is minimal: last-token-index, a small k/v window pointer, model-compat hash, and a zone tag. Default TTL 90s-180s (configurable per-tenant). Backing store: sharded in-memory with bounded size + LRU eviction.

nate: We need metrics & billing signals: resume success/fail, and reason codes. Also surface resume count in SLO dashboards.

alicia: Proposed metrics: `edge_cp_created`, `edge_cp_resume_attempt`, `edge_cp_resumed`, `edge_cp_reject_reason` (expired, zone-mismatch, model-incompatible). Tracespan should link original request_id -> cp token.

marta: Handshake sketch:

Client initial stream:
    -> POST /v1/assist/stream
    Headers:
      Authorization: Bearer ...
      X-Edge-CP: 0  # no token
Edge response:
    <- 200 OK (stream)
    Headers:
      X-Edge-CP: cp_Zz12ab

Client disconnects mid-stream, retries:
    -> POST /v1/assist/stream
    Headers:
      X-Edge-CP: cp_Zz12ab

Edge tries soft-resume: if successful -> 206 Partial Content (continuing stream). If cannot resume -> 409 Conflict + `X-Edge-CP-Reason: <reason>`.

sam: Regional routing: if retry hits a different zone we should generally reject resume. Cross-zone resume is doable later but requires token replication and stronger consistency. For now zone-scoped tokens.

jade: Admin operations: force-revoke tokens (compliance / GDPR), and an endpoint to bulk-expire a tenant's tokens.

infra-bot: perf note: simulation with 2m TTL and average 8k rps shows ~2% memory increase on ingress hosts. Recommend tenant opt-in flag + global kill-switch.

alicia: Ops checklist: console toggle, small dashboard cards, RBAC for revoke. Docs: clear client contract stating resume is best-effort and clients must implement fallback to a fresh stream. SDKs should default to retrying once with token and then fall back.
