alex: Quick UX question — we need to design how Console exposes the automatic safety-switch for rollouts. Not asking about the runtime routing algorithm, just the UI/labels and what knobs to expose to customers.

maria: Do we have a canonical list of triggers? e.g. 5xx rate, p95 latency, timeout count, degraded-accuracy alerts from evals?

sam: Short answer: yes. Ops telemetry wants: error_rate (1m/5m), p95 latency, timeouts/sec, and a custom alert webhook. Those should map to simple toggles + threshold inputs in the UI.

kevin: UX nuance: customers misunderstand "fallback" — can we call it "safety switch / escape hatch" and show the action as "route to backup model"? Less scary than "serve degraded outputs". :thinking_face: 

maria: +1 on naming. Also suggest a preview mode: simulate routing for 1% of traffic for 10 minutes so they can see token cost delta and latency change.

alex: Good. What exact controls? My draft:
- enable safety switch (on/off)
- triggers (multi-select) with thresholds
- action: route to (model variant) OR return structured error OR queued retry
- canary percentage and duration
- audit log link + recent trigger history

sam: Add: an "override" API key scope that allows programmatic bypass (for infra teams). Also: per-route quota impacts should be shown (tokens saved estimate).

kevin: UI copy idea: "When enabled, Redwood will automatically detect service degradation and route traffic to a configured backup to keep your app responsive. Audits and canaries included." Short and action-focused.
