Alex: Quick Q about embeddings endpoint contract — we need a single canonical answer for SDKs/docs: allowed input types, truncation behavior, batch limits, and what the response shape is for single vs batch inputs.
Maya: Short answer: accept string OR list[string]. Normalize server-side to a list to avoid branching client code.
Sam: Agreed. Important: always return an array of embeddings (one per input) rather than a bare vector for single input — avoids breaking clients. Include an explicit `index` on each item so callers can reorder if they sent mixed types.
Jess: What do we do for inputs that exceed the model token limit? truncate silently, return warning, or error 413?
Maya: Proposal: two-tier behavior:
- If input <= soft_limit (e.g. model_token_limit) -> normal encode.
- If input > soft_limit but <= hard_limit -> truncate (right-side) and return 200 with per-item warning metadata (do not silently drop).
- If input > hard_limit -> reject with 413 (payload too large).
Sam: Concrete numbers for current embed models: soft_limit = model_token_limit (e.g. 8192 for redwood-embed-1), hard_limit = 65536. We'll put exact values in model metadata.
Alex: How should the SDK surface truncation warnings? Exceptions? metadata?
Maya: Add a `warnings` array in the response body with items: {index, code, message, original_length, truncated_to}. Also add response header `X-Redwood-Embeddings-Warnings: 1` so lightweight clients can check headers.
Jess: Example request/response would help for docs.
Alex: Example (pseudo):
```
POST /v1/embeddings
{
  "model": "redwood-embed-1",
  "input": ["short text", "very long text ..."]
}

200 OK
{
  "model": "redwood-embed-1",
  "data": [
    {"index": 0, "embedding": [0.001, -0.23, ...]},
    {"index": 1, "embedding": [0.12, 0.003, ...]}
  ],
  "usage": {"input_tokens": 9200, "output_tokens": 0},
  "warnings": [
    {"index": 1, "code": "truncated", "message": "input truncated to model token limit", "original_length": 12000, "truncated_to": 8192}
  ]
}
```
Sam: Important detail: embedding vector length varies by model (e.g. redwood-embed-1 = 1536). Do not let clients assume fixed dim — include `model_dimensions` in response body to be explicit.
Maya: +1. Add `model_dimensions` top-level field and document that `len(data[i].embedding) == model_dimensions`.
Jess: Batch limits? We need a hard per-request item cap for memory/throughput planning.
Sam: Recommend per-request item cap = 256 by default for hosted API, with a soft cap for Dedicated customers configurable. Also add an overall token cap per request (sum of tokens across items) to avoid OOM. If limit hit, return 413 with a human-readable message and `retry_after` when applicable.
