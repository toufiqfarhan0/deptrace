ana: quick RFC follow-up: proposing we centralize resume checkpoints at the gateway and drop opaque multi-hop resume tokens. sketch attached inline, want quick sanity check before PR.
chris: quick summary?
sasha: please, short bullets.
ana: bullets: 1) gateway owns compact checkpoint (offset + small prefix metadata) instead of passing opaque token through proxy chain; 2) clients reconnect with same Idempotency-Key + Resume-Offset; gateway validates and resumes if within window; 3) resume is opt-in per-route via `resume.enabled` and guarded by `X-Resume-Safe` header to avoid duplicating side effects; 4) legacy resume-token compatibility layer for one release.
jun: big simplification. downside: gateway memory for checkpoints. how bounded?
ana: bounded by route config `resume.window_tokens` (default 4k) and `resume.max_checkpoints`. eviction LRU or on-conn-close. also checkpoint can spill to object storage.
mike: object store means additional fetchs on resume. latency hit?
ana: yes. plan: in-memory first, S3 fallback when memory pressure. config `checkpoint.storage = [memory|s3|hybrid]`.
sasha: how does upstream reconstruct KV cache now that we removed token blob?
ana: gateway writes an immutable checkpoint blob (encrypted, per-tenant) to object store when needed and passes `X-Checkpoint-Ref` to upstream. upstream fetches if it needs to reconstruct state. small resumes may inline prefix metadata instead of full fetch.
chris: security: need KMS + per-tenant ACLs on blobs.
ana: yep. encrypt with KMS and namespace blobs per-tenant/route. add TTL and auto-delete after checkpoint expiry.
jun: rollout: feature gate off by default. enable for internal services in staging, then 1/10/50/100% canaries.
ana: compatibility: gateway accepts legacy resume tokens and converts them to internal checkpoint format in translator module. keep translator for one release.
mike: client contract: require Idempotency-Key and optional Resume-Offset. what if client lies about offset?
sasha: gateway will reject (409) if offset > checkpoint or resume not allowed. clients should backoff and retry fresh request.
ana: handshake sketch:

```
Client -> Gateway: POST /v1/generate (Idempotency-Key, X-Resume-Safe: true|false, Resume-Offset?)
Gateway -> Upstream: normal streaming call (no opaque resume token)
On transient failure: Client reconnects with same Idempotency-Key + Resume-Offset
Gateway: if checkpoint exists and offset <= checkpoint_offset && route.resume.enabled, resume flow (pipe prefix metadata or checkpoint-ref to upstream); else 409/resume-required
```
