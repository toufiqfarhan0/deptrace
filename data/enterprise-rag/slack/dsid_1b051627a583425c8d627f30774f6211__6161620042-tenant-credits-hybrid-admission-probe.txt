devon: RFC follow-up: exploring a hybrid lease+token admission tack to reduce global coord while keeping fairness. want quick sanity-checks.
tara: sketch it? short bullets ok.
devon: idea: each front proxy keeps a small local lease pool per-tenant (fast, ephemeral). a central allocator issues ephemeral "credits" that replenish pools on a slow cadence. tokens still exist for absolute hard caps.
izzy: so two levers: local-lease for latency and central credit for fairness. what's the eviction/revocation story?
devon: central allocator can set a policy flag on credits: normal | probation | restricted. probations lower replenish rate. revocation: publish InvalidateCredit(credit_id) -> proxies drop future attaches. in-flight attached leases run to ttl.
leo: main gap: how to avoid double-counting when a request gets a local lease and later central credits also account for it? we must pick a single accounting place.
chandra: we can mark a lease's origin: ORIGIN=local|central. Accounting increments only when origin==central or when local falls back to token-deduct path. simple rule: central credits are charged on acquisition; local leases are free until they convert.
tara: conversion rule needs to be deterministic. e.g., if local TTL expires and request retries, that retry tries central acquire and then gets charged. but what about long-running streams?
devon: streams: require periodic heartbeat that re-attaches to central credits every N tokens. default N = 256 tokens. if central denies, fallback to strict local-only rate limiting for remainder.
izzy: abuse prevention: central allocator uses a rolling abuse_score per-tenant. if score > threshold we stop replenishing central credits and drop tenant to local-only with aggressive token burn. define metric: abuse_score_lookback = 5m.
leo: how compute abuse_score? combine rps spike delta, error-rate spike, suspicious pattern heuristics (identical prompts, high cost tokens). need a lightweight stream detector; can't add heavy compute in hot path.
chandra: detector should be offline-ish: sample 1% traffic and run heavier heuristics, produce signals to allocator. fast path uses EWMA of rps+5xx. heavy signals are advisory.
tara: interface: AcquireCredit(tenant, route_hint, requested_ru) -> credit_id, granted_ru, ttl_s, policy_flags. AttachLease(credit_id, request_id) -> lease_id. DetachLease(lease_id) async. Publish InvalidateCredit(credit_id, reason).
devon: proto stub later. also propose header to clients on degrade: X-RW-Admission: fallback=local|denied|central. helps SDKs choose local retries or model fallbacks.
izzy: metrics: credit_replenish_latency, credit_replenish_count, local_lease_hit_ratio, conversion_rate, blocked_by_abuse. need dashboards and alerts on conversion spikes.
leo: SLO thought: maintain p50 latency for small requests < 100ms when using local leases. central acquire must not be on critical path: make it async replenish.
chandra: persistence: keep credit grants in a short-lived KV (TTL = 24h) for audit. store only metadata to avoid perf hit.
tara: billing interplay: if central revokes credits mid-window, billing must not auto-charge customers for lost credits. create event: credit_revoked -> billing.review.
devon: rollout plan: start with opt-in tenants in beta, run for 2 weeks with manual ops guardrails. escalate to probation mode if false positives > 0.5% users affected.
izzy: ops checklist: 1) dashboard 2) incident runbook 3) kill-switch to disable central allocator 4) sampling pipeline for heavy heuristics.
leo: open question: granularity of credits (tenant vs tenant+model). I'd start tenant-level then refine to per-route for a few big PLG tenants.
chandra: agree. also circle on TTLs: local lease TTL = 50-150ms, credit ttl = 1-5s elastic. tune by experiment.
