devin: can you paste a minimal repro?

miriam: Node SDK v2.5.1-rc, snippet from bootstrap: 
```js
await admin.createRoute({
  serviceId: 'sample-ops',
  name: 'chat',
  model: 'redwood-2.2',
  autoscale: { min: 2, max: 20, target_util: 0.6 },

```
After creation GET /admin/routes/:id shows autoscale=null and concurrency=1.

tomas: I repro'd locally. Looks like the SDK proto flattens autoscale into top-level fields (`autoscale_min`, `autoscale_max`) for some historical reasons, while the server RPC expects a nested `autoscale` object. The REST gateway has a compatibility layer that rebuilds the nested object for curl clients. SDK is sending the flattened shape and server ignores unknown flat fields, falling back to defaults.

miriam: that explains why users following quickstart get silently underprovisioned routes. Very bad DX.

devin: two problems surfaced: (A) parameter shape drift (nested vs flattened) and (B) idempotency header handling. When onboarding runs hit 429s, SDK retries but doesn't preserve Idempotency-Key header on the retry due to our internal retry wrapper re-issuing the request without copying custom headers. That leads to duplicate create attempts or inconsistent server-side dedupe.

qa-bot: running impacted tests: onboarding/quickstart/route-provisioning -> fail 3/3.

sre: to mitigate: short-term workaround is to call REST directly with explicit nested autoscale in the payload: 
```bash
curl -X POST https://api.redwood.ai/admin/routes \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"serviceId":"sample-ops","name":"chat","model":"redwood-2.2","autoscale":{"min":2,"max":20,"target_util":0.6}}'
```

miriam: leaving a quick README patch with that workaround. But we need an SDK fix: normalize both shapes (accept nested `autoscale` and flattened `autoscale_max`/`autoscale_min`) and always serialize the nested object to match the RPC contract. Also add a deprecation warning when flattened fields are used.

devin: for idempotency: change retry wrapper to preserve arbitrary headers (including `Idempotency-Key`) when re-sending, and default to auto-generate an idempotency key for mutating admin ops if none provided. We'll gate auto-retry-on-429 behind presence of idempotency key by default (auto-gen sets it). Server-side needs to ensure dedupe is robust.
