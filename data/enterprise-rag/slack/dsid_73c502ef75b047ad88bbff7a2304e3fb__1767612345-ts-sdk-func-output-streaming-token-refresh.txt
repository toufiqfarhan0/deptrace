Erin N: Heads up — hitting a weird edge when using the TS SDK function-calling helpers + streaming + auth-refresh retries. Repro below.

Erin N: Steps: start stream -> token expired mid-stream -> SDK refreshes token and retries chunk -> downstream sees argument types as strings (enums and numbers become strings).

Erin N: Minimal snippet:```ts
const res = client.stream.chat.responses({
  model: 'redwood/fn-1',
  input: prompt,
  functions: [{name: 'getUser', ...}],
});
for await (const chunk of res) {
  // chunk.function_call.arguments expected {id: number, mode: 'FULL' | 'SUMMARY'}
  // actual: {id: "123", mode: "full"}
}
```

Derek L: interesting. Is this only TS or do we see same in Python?

Erin N: Seen in local Python repro too but less common — I think JS runtime path is culprit because of streaming parser + stringify step on retry.

Paul K: quick hypothesis: when we retry we re-emit buffered raw text, but we then run it through JSON.parse once and never run schema coercion/enum normalization hooks that the non-streaming path runs. So typed helpers (TS) lose runtime normalization.

Derek L: can you paste a raw chunk from logs?

Erin N: raw chunk after retry: ```json
{"type":"function_call","name":"getUser","arguments":"{\"id\":\"123\",\"mode\":\"full\"}"}
```
notice arguments is a string (double-encoded).

Paul K: aha double-encoded is the smoking gun. Streaming parser probably concatenates partial frames then wraps them as string to preserve chunk boundaries. When retrying we re-emit that wrapped string instead of the original object.

Derek L: options: 1) avoid double-wrapping at source (hard), 2) SDK helper that detects stringified arguments and reparses & runs type coercion hooks, 3) change retry to replay original parsed events (needs buffering). I lean to (2) as lowest risk.

Erin N: option 2 works for us now — we'd add a small util in SDK: `normalizeFunctionCall(chunk, schema?)` that tries JSON.parse on chunk.arguments if it's a string, then runs optional schema coercion (enum lower/upper normalization, string->number coercion).

Paul K: agree. For TS we'd add runtime validators using zod/ajv as an opt-in param: `stream.chat.responses({..., normalizeFunctionCall: { schema: myAjvSchema } })` so users can opt-in to stricter behavior. Default should just reparsed JSON and basic coercion for numbers/enums.

Derek L: also consider perf: parsing every chunk could be heavy. Make it lazy: only attempt reparsing if typeof arguments === 'string'. Ok to do small microbench.

Erin N: another wrinkle: auth-refresh may cause duplicate function calls on service side if retries not idempotent. We should attach `x-rw-retry-id` and dedupe server-side but SDK should also mark retried chunks with `{__retried: true}` meta so apps can guard.

Paul K: good call. I'll add meta flag and also a per-stream `maxRetryReparseAttempts` option.
