maria.g: Heads up — quick sync about enrichment SLA/grace periods and fallback behavior when billing keys or tenant attrs arrive late. We've seen a couple of user-facing cost reports misattributed after last week's deploy.
aj: Which flows exactly? edge pre-enrich vs late pipeline?
maria.g: Mostly late-enrich path. Example: frontend sends minimal envelope → edge forwards → sampler drops high-card attrs → late-enrich job picks them up from trace-store later. If billing_key arrives only in late-enrich, cost accounting misses the window and shows undercount for tenant A.
sam.k: Oof. Do we have metrics on how often billing_key is late vs missing entirely?
maria.g: ~0.9% of traces in last 7d had billing_key added post-ingest (by late-enrich). ~0.05% had it never appear. Numbers from query run (internal link).
kevin_ops: Tradeoffs: if we extend SLA/grace period for attribution we increase retention window and CPU to perform backfills. Also storage+query cost.
aj: Options: 1) Raise attribution window to 24h and run batch backfills. 2) Make late-enrich emit a light-weight attribution event that increments counters async (cheap). 3) Fail closed — mark as unknown and leave to billing pipeline to reconcile.
sam.k: I like option 2. Emit a minimal 'billing patch' delta that the billing pipeline consumes; keeps queries small.
maria.g: Option 2 requires idempotency and ordering guarantees. Late-enrich job might run multiple times for same trace id. We'd need a dedupe key or use monotonic versioning.
kevin_ops: We already have an idempotent write token for span-index service. Could reuse a similar pattern: dedupe key = trace_id + attr_set_hash. Also need TTL.
aj: Concern: query correctness for dashboards that show near-real-time cost. If we apply patches async, dashboards will temporarily show gaps. Acceptable?
maria.g: Product is okay with small lag if we surface a marker on UI like 'attribution pending' for up to X hours.
sam.k: Implementation sketch:
```
- late-enrich emits /billing/patch with {trace_id, billing_key, ts, attr_hash}
- billing consumer applies patch to cost_shard if not already applied (check attr_hash)
- emit metric: billing.patch.applied / billing.patch.duplicate
```
