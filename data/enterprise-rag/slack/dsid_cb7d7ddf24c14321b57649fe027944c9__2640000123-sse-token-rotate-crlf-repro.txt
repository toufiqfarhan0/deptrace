mina: looks like CRLF is being injected between consecutive chunks. our parse code only splits on "\n\n" and concatenates lines starting with 'data:'. leading CRLF makes the new JSON look like a continuation.

chris: two-pronged fix: 1) normalize CRLF->LF before splitting, ignore lines starting with ':'; 2) clear partial buffer synchronously when abort() is called, then schedule reconnect on next tick. pseudocode:

```
onAbort(){
  partial = '' // clear immediately
  setTimeout(connect,0)
}
onData(chunk){
  buf += chunk.replace(/\r\n/g,'\n')
  processEvents(buf)
}
```
