lee: Quick follow-up on abort semantics for streaming - proposing a small, pragmatic feature set we can ship this sprint. want to avoid another big RFC cycle.

anya: Love it. What's the minimal surface?

lee: Minimal: 1) accept header `x-rw-abort-preference: immediate|brief-hold` 2) brief-hold = 500ms local grace where gateway keeps upstream alive for potential fast reconnect/hedge coordination 3) return `x-rw-resume-allowed: true|false` when client disconnects.

carlos: Important: hedging logic needs to be resume-aware. If a brief-hold exists hedges should be suppressed for that request id for the grace window. Otherwise we risk duplicate side-effects.

mika: Resource pressure question: snapshots or keep connections? For MVP, don't snapshot. Keep the upstream connection open but mark it low-priority so schedulers can preempt it under memory pressure. Add an eviction hook in admission controller.

infra-bot: infra: connection-pool usage active=910/1000, reserved=20.

anya: We should also add a resume id returned on disconnect: `x-rw-resume-id: <opaque>` so SDKs can try to reattach. Make resume-id single-use or TTL-limited (default 30s).

lee: Agreed TTL 30s. Also require original auth token to rebind. No cross-tenant reattach. Security binding explicit in proto.

carlos: For correctness, resume should not change model/version. If the new attempt has different params return 409 + `x-rw-resume-error: mismatch`. That forces clients to re-issue clean requests rather than mismatch rebinds.

mika: Observability: emit `edge.abort_pref.hold.count`, `edge.resume.binds`, `edge.hold.evictions`. Add traces linking resume-id across gateway logs.

anya: Billing: if upstream continues running during grace, how to charge? For Hosted, platform absorbs short holds <1s; for Dedicated we surface a `grace_hold_ms` meter in usage. Product will decide after we ship metrics.

lee: Pragmatic hedging rule: do not spawn hedges during active brief-hold unless caller sets `allow-hedge=true`. Hedging can consult the resume store; if a resume record exists suppress hedges.

carlos: Edge-case: client disconnects then reconnects after hold expired but upstream still running; we should return a 409 and let client restart. Better than attempting a risky partial reattach.
