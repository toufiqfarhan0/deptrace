Elena Park: Noticed our telemetry and SDKs disagree on client-visible failures when routing falls back. Console shows mixed badge states. We should standardize a small error contract so SDKs, console, and alerts align.

Mohammed Khan: +1. Lightweight proposal: top-level field client_status (OK/RETRYABLE/THROTTLED/FAILED), reason_code (RATE_LIMIT|TIMEOUT|MODEL_OOM|BACKEND), route_origin (string), retry_after_ms optional, visibility_level (public/internal), visible_message_key optional for i18n. Keep visible_message short and templated.

Yara Okonkwo: Important: route_origin is high-cardinality. We should avoid it in primary rate metrics and use it only as a facet in logs/dashboards. For console badges, aggregate route_origin to categories (primary, fallback-small, fallback-quantized).

Elena Park: Agreed on aggregation. For SDK behavior: map client_status -> typed exceptions. If visibility_level=public the SDK should resolve visible_message_key via locale bundle; if internal, surface a generic message. Backcompat: if client_status missing, SDK should fallback to legacy mapping (429 -> THROTTLED, 5xx -> FAILED).
