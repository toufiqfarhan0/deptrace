maria-support: Customer (ACME) reports intermittent 401s and says they can't find any request/trace ids in their logs or our Console. They attached screenshots but no header shows an ID. Can we get a reproducible checklist to send them?

liam-eng: quick checklist I use: ask for (1) endpoint path + method, (2) earliest and latest timestamps (UTC), (3) exact request headers (screenshot or raw), (4) a HAR or curl that reproduces, (5) account-id / user-id / session id if available. Also ask whether they sit behind a proxy or CDN that might strip headers.

maria-support: good — they say they run through an edge proxy & mobile apps. they also say the web console doesn't show request ids for these requests. any platform-specific tips?

tess-mobile: mobile tips: enable SDK verbose logging in app build or use Charles/Proxyman to capture TLS. For iOS native SDK set: `Redwood.configure(debug: true)` and look for logs containing `request_id` or `rd_request_id`. For Android call `Redwood.setLogLevel(LogLevel.DEBUG)` or check `/data/data/<packagename>/files/redwood/session.json` (if they can pull a file) — it often has `last_request_id` or `session_id`.

liam-eng: web: ask them to open DevTools -> Network -> filter by `api.redwood` or `/v1/`. Click one failing request and check Request Headers and Response Headers for `x-request-id`, `x-rd-request-id`, `redwood-request-id` or `redwood-debug-token`. If they use fetch/XHR, also check for `initiator` and console logs. Note: some browsers/hardened extensions hide auth headers in exported HARs — ask them to capture full request (preserve log, include request bodies).

samir-infra: proxy/CDN gotchas: many gateways (Cloudflare, Fastly, AWS ALB, or corporate proxies) can drop or rewrite custom headers. Ask customer to check ingress rules for header removal or header whitelist. If they have an API gateway, they should enable passing through `X-Request-Id` and any `redwood-*` headers. If headers are stripped, fallback is searching our logs using: time window + client IP (if they can provide), path, and account id.

liam-eng: example minimal curl we ask them to try (replace placeholders):

```
curl -v -X POST https://api.redwood.ai/v1/generate \
  -H "Authorization: Bearer <REDACTED_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-small","input":"test"}'
```

liam-eng: after that, tell them to paste the `*server response headers*` (not just body). On success/fail the response should include `x-request-id` or `redwood-request-id` we can correlate. If the response shows nothing, the header was likely stripped before reaching our edge or removed by the client.

maria-support: if they can't run curl, what minimum info do we need to escalate to eng?

liam-eng: minimum for escalation: UTC timestamp range (±2m) when the failure happened, endpoint path (e.g., `/v1/generate`), account-id (or project id), sample user-agent, and any local trace or SDK logs. If they can produce a debug token from Console -> Support -> Create debug bundle, include that token. We can use the token to fetch the bundle.

tess-mobile: note re: HAR and mobile: HAR exports from browser are usually OK. For apps, recommend Charles/Proxyman with SSL proxying enabled. Instruct them to install our SSL cert in the device emulator or real device to capture request/response headers and bodies.
