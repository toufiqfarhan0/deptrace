ivy (PM): hey team — dropping a fresh mock for the Alerting SLO config. focus areas: 1) clearer threshold affordances (visual hints for p50/p90/p95), 2) explicit "Silence duration" (users asked for finite windows), 3) compact notification preview with keyboard-first expansion. figma: https://figma.redwood/alerts/threshold-hints
sam (Design): nice — I sketched a small helper row under the threshold input that shows three micro-stats: p50 / p90 / p95 with suggested preset values. idea: when hovering a preset show a light inline tooltip: "Applies to p95 by default" and offer a link "edit which percentile" to switch metric target. keeps the main flow simple for newbies.
jorge (Frontend): implementation notes: the helper row is static DOM; on hover we can lazy-load more detailed samples. for the notification preview we'll show up to 2 recipients inline and a "+N" button that opens an overlay. overlay will be lazy-mounted. also request: debounce preview re-renders by 300ms to avoid hammering the previews microservice.
pat (A11y): a11y asks: helper row stats should be reachable by keyboard and announced (e.g., "p95: default 1.2s"). the "edit which percentile" link must focus the percentile selector. the +N trigger needs aria-expanded and an accessible label like "Show 3 more recipients". overlay should use role=menu since each recipient has actions.
ivy (PM): product would like an explicit "Silence duration" control rather than an on/off only. propose presets (15m, 1h, 8h, 24h) + Custom. show the remaining time in the incident timeline UI when a silence is active. also add helper copy: "Silences stop notifications for the selected window; incidents are still recorded."
sam (Design): UI idea: a compact dropdown for duration with text like "Silence for 1 hour". when set, show a small pill in the preview header: "Silenced — 59m left". if user picks Custom open a small inline numeric input with unit select (m/h/d). show an undo action after setting a silence for 8s.
jorge (Frontend): backend notes: persist both fields — `silence_duration` (iso8601 or seconds) and `silence_until` (timestamp) so frontend can show remaining time without server roundtrip. suggested payload:
```
{
  "preset_key": "critical_v1",
  "manual_threshold": "p95>1.5s",
  "silence_duration": 3600
}
```
we can compute silence_until client-side: now + duration. will coordinate with api team if they prefer server-side compute.
pat (A11y): accessibility for silence pill: when silence is active announce via aria-live: "Alerts silenced for 1 hour". the pill must be keyboard-focusable and pressing Enter opens a small panel to extend or cancel the silence. ensure focus trapping in that panel and an accessible close. contrast wise the pill should meet 4.5:1.
sam (Design): compact notification preview: show first two recipient chips + a slim "+N" chip. chips show channel icon (email/slack/pd) and initials fallback. when overlay opens include per-recipient actions: simulate, remove, mute destination. include a small "simulate all" CTA at the top.
jorge (Frontend): sample simulate payload for the modal (for design & QA):

I'll wire the modal to the notif-preview service; for the mock we'll use the static sample. debounce updates and lazy-load avatars as discussed.
ivy (PM): UX copy tweak: prefer "Silence" (verb) in controls but show noun "Silences" in lists. small microcopy under duration: "Silences stop outgoing notifications for the selected window but keep the incident in history for auditing."
pat (A11y): keyboard flows: Tab into recipients strip, Tab to +N, Enter to open overlay, Arrow keys to navigate menuitems, Enter for action. When silence is set, automatically focus the silence pill and announce remaining time. toasts must be dismissible and focusable; avoid auto-dismiss for keyboard users.
sam (Design): one more: show a tiny analytic hint under preset chips: "Used by 32 alerts" on hover — helps teams know impact. This is optional but product likes it.
jorge (Frontend): performance note: the incident timeline preview (live) is expensive. we'll ship with a static illustrative timeline and a small badge "Live timeline coming soon". also we should cache preview results per-session to reduce calls.
