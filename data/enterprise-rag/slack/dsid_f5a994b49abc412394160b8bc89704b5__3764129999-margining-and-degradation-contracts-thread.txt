oliver: Quick follow-up from the RFC — we need a lightweight contract for "precision margining" when switching between FP8/INT8/4bit. Goal: make degradation predictable for downstream apps and give operators clear rollback triggers.
lucy: +1. can you outline the minimal signals we should expose?
oliver: Thinking of three signals: 1) deg_score (0-1) per-slice, 2) sample-level drift count, 3) model_variant tag (e.g. fp8-safe,int8-constrained,4bit-fast). Also a per-request header: X-Precision-Used.
raj: For deg_score, do we compute on eval prompts only or live-sampled user traffic?
oliver: Both. Eval runs are baseline; live-sample is rolling. We use rolling-window average and p90 for alerts.
tia: How do we define thresholds? Business wants low false positives.
oliver: Proposal: two-tier thresholds: advisory at 0.03 p90, hard at 0.08 p90 — numbers are normalized delta from float32 baseline on our standard eval set.
akshay: Can we correlate deg_score with user-facing metrics (click-rate, conversion) for customers?
oliver: We'd emit a per-customer correlation job (daily) that maps deg_score->quality delta. That will be opt-in initially.
lucy: Operationally: add route metadata so Redwood Console can show which endpoints are on which precision lane.
oliver: Yep; new route fields: precision_profile and precision_history (recent variants). Example config we could add to runtime:
```
route_precision:
  default: fp8
  fallbacks: [int8, 4bit]
  quality_hysteresis: 0.015
  alert_p90: 0.08
```
raj: quality_hysteresis — good. prevents flapping. How long should hysteresis window be?
tia: Maybe proportional to traffic. Suggest min 5m, max 2h.
akshay: For fallback ordering, we should prefer variants that keep attention kernel identical to avoid KV cache misses. e.g., prefer int8 variant compiled with same attention kernel before switching to 4bit.
oliver: Agreed — add kernel_compat tag to variants and prefer same-kernel fallbacks.
lucy: What about AB testing? If we roll a new 4bit profile, can we route e.g., 5% to it and monitor deg_score and latency?
