frank: That's the root cause: two installations in PATH and they use different default profile roots. The migrate command was written to be conservative when it sees non-home source paths. For a safe manual migration: 1) pick the binary you want to keep (tarball in /opt or apt one), 2) ensure it is the one on PATH (remove duplicate wrappers), 3) stop service if running, 4) reindex by removing corrupt index and running `redwoodctl profile import` for each file. Example steps:
```bash
# pick /opt/redwood as canonical
sudo rm /usr/bin/redwoodctl || true
sudo ln -s /opt/redwood/bin/redwoodctl /usr/local/bin/redwoodctl
# ensure only one binary
which redwoodctl
file $(which redwoodctl)
# fix profiles
rm -f ~/.redwood/index.json
for f in /etc/redwood/profiles/*.json /opt/redwood/.redwood/*.json; do
  cp "$f" ~/.redwood/ || true
  chown $(id -u):$(id -g) ~/.redwood/$(basename "$f")
  redwoodctl profile import ~/.redwood/$(basename "$f")
done
redwoodctl profile list
```
That sequence imports profiles into the active index using the chosen binary's import logic.
