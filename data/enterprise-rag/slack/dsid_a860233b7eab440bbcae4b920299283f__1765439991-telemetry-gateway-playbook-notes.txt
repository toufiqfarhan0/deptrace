elaine: quick proposal 
We need a concise playbook for the telemetry gateway when route quotas cause reroutes. Goals: deterministic sampling, provenance for debugging, short-lived unmask for SREs, and an encrypted audit-mode for compliance. thoughts?

raj: +1 deterministic. suggest per-tenant rate via hash(customer_id) % 100 < pct so decisions stick across retries. allow per-route override.

maria: audit-mode: capture full req/res but write to encrypted audit bucket (KMS) with 7-day TTL and strict access workflow (legal+sec). make opt-in per-tenant.

jen: console UX: add an "Inspect" action that opens a short session (5-30m) requiring reason, logs approver and shows sample_decision + RBAC check.

frank: operational worry: changing hash keys or rules splits traces. we should emit a provenance_id at ingress and include sampler_version and sample_reason in headers so dashboards can reassemble.
