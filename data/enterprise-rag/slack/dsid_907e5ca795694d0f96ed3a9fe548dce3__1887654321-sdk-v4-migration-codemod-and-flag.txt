Jordan K.: Quick update: we pushed a docs + migration toolkit for the SDK v4 "param strictness" change. Link below. :loudspeaker:
Maya S.: nice! what does the toolkit include?
Jordan K.: three things: 1) a codemod `redwood-migrate-params` to rewrite common legacy arg shapes, 2) a console feature-flag `legacy-param-compat` for Dedicated customers, 3) CI lint and smoke tests.
Liam P.: codemod usage example?
Jordan K.: `npx redwood-migrate-params ./src --rules=truncate,aliases --dry-run` then remove `--dry-run` to apply. We included a Python script wrapper too.
Maya S.: ok, good for bulk upgrades. What about teams that want zero-change for now?
Jordan K.: two options: pin to the last v3 patch or flip the console flag / env var. Pin example: `redwood-sdk==3.17.0` or "@redwood/inference": "3.17.0".
OpsBot: Admin flag created: Console -> Admin -> Feature flags -> legacy-param-compat (Dedicated only). Private customers have an env var `RW_LEGACY_PARAM_COMPAT=1` for the time being.
Liam P.: how long will the flag/shim be available?
Jordan K.: we intend to keep the flag available for 60 days after v4 GA; codemod + tests should make upgrades low-friction. Exact sunset date will land in the migration doc.
Maya S.: any CI snippets we can copy?
Jordan K.: yep: `pip install redwood-compat-lint` and GH Actions snippet in the guide to fail on deprecated param usage.
Liam P.: telemetry to estimate impact?
Jordan K.: opt-in telemetry collects param-name shapes and counts (no payloads). SQL fingerprint example is in the toolkit so teams can estimate affected callsites.
Maya S.: who to ping if something breaks during rollout?
Jordan K.: ping me (@jordan) or post in #eng-runtime; open an infra issue with label `sdk-migrate` and well coordinate.
