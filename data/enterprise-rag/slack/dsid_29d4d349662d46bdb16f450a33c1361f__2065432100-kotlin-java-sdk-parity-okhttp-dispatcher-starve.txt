ivy: about parity, we discovered our Java sample used a custom Call.Factory that rewraps Request to add headers at enqueue time, while Kotlin sample applied headers in an Interceptor. When retries happen at connection layer, interceptor headers can be lost in some edge cases while factory-wrapping survives. That's why behavior differed.

diego: small snippet for single in-flight refresh (Kotlin): ```kotlin
private val refreshLock = Mutex()
private var refreshDeferred: CompletableDeferred<String>? = null
suspend fun refreshToken(): String = coroutineScope {
  refreshDeferred?.let { return@coroutineScope it.await() }
  refreshLock.withLock {
    refreshDeferred?.let { return@withLock it.await() }
    val def = CompletableDeferred<String>()
    refreshDeferred = def
    try {
      val token = networkRefresh() // suspend network call
      def.complete(token)
      token
    } catch (e: Exception) {
      def.completeExceptionally(e)
      throw e
    } finally {
      refreshDeferred = null
    }
  }
}
```
