Some bundlers (and certain Next.js SSR adapters) prefer the ESM export and then transform it, which ends up calling into a runtime path that doesn't initialize the auth wrapper in our code (we have a small `if (typeof globalThis.fetch === 'function')` branch that behaves differently).

olivia: Customer asked if there's a change they can make in next.config.js to avoid the issue without changing imports.
me: For Next.js, they can disable ESM optimization for that package by adding to webpack externals/next config to prefer the CJS entry, but it's brittle. Example snippet:
```
webpack: (config, { isServer }) => {
  if (isServer) {
    config.externals = [...config.externals, function(context, request, callback) {
      if (request.includes('redwood-inference')) return callback(null, 'commonjs ' + request)
      callback()
    }]
  }
  return config
}
```
