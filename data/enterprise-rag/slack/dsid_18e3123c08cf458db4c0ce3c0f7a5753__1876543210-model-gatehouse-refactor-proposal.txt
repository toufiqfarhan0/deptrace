miriam: quick proposal - I'm calling this the 'gatehouse' refactor for model ingress. idea: replace the monolithic intake job with a small sequence of fast, deterministic "fitness" checks we can run early and repeatedly. keeps heavy benching for later and lets runtime route around known bad builds.

ken: curious, what are the core checks? latency-only smoke?

miriam: short list: 1) signature/shape + tokenizer sanity 2) microprofiling hotpath (single-step seqlen slices) 3) perf fingerprint (compact vector) 4) deterministic output test on golden prompts 5) policy + rollout hints (e.g., require dedicated canary if fingerprint diverges)

samir: how small is the perf fingerprint? storage + compare costs matter.

miriam: aim <1KB per model: a handful of quantiles + a hash of activation shapes + a tiny embedding of tokenization distribution. compares with cosine + a simple threshold.

dev-bot: CI run queued: https://ci.redwood/example/ingest/1876543210-results

ken: what about model variants (quantized vs fp16) - need to treat as separate entries?

miriam: yes — variant-level gate. treat artifacts as (model, compile-config, qprofile). fingerprint computed post-compile so it's representative.

olivia: observability ask: do we keep raw microprofile traces or only aggregates? storing traces for every ingest will blow logs.

miriam: store aggregates in primary DB + push full trace to cold storage on failures. telemetry will emit a lightweight event with: fingerprint_delta, latency_p50/p95, tokenizer_mismatch (bool).

samir: fallback behavior: if fingerprint deviates but deterministic outputs match, what's the route? allow or reject?

miriam: default: allow with a 'cautious' rollout - route 10% traffic via canary for 24h, run quality evals. ops can flip to block in 1-click if problems.

ken: any risk of adversarial model uploads passing checks? e.g., poisoned tokenizer that only shows in deep eval.

miriam: yep — this isn't a full safety system. the gatehouse is meant to triage and speed harmless/obvious failures. safety and deep regression evals still run later in the pipeline and can trigger retraction.
