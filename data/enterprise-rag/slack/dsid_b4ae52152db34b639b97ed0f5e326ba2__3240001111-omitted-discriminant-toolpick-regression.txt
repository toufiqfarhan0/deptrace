devin_eng: I tried a quick repro with our py 2.3.1 client: when using a dataclass wrapper around bytes and the dataclass __post_init__ leaves the field as memoryview, our JSON encoder hit a path that coerces memoryview -> str via str(memoryview(...)) which yields "<memory at 0x...>" or empty in some windows builds. In TS the Buffer -> JSON path hits Buffer.prototype.toJSON which returns { type: 'Buffer', data: [...] } unless JSON.stringify is used on Buffer directly in some bundlers which produces {} or "". Go's json.Marshal([]byte) returns base64 by default, so it's surprising go shows empty string — need to confirm whether they used a custom marshaller or a proto wrapper.

devin_eng: Proposed short-term SDK changes:
- py: ensure bytes-like objects are base64-encoded by our toolcall encoder, not passed to json.dumps as-is.
- ts: if arg is Buffer/Uint8Array, serialize as base64 string instead of relying on JSON.stringify.
- go: verify that the client payload is not being re-encoded through an intermediate string conversion.
I'll open a PR, add unit tests for dataclass/memoryview/Buffer -> toolcall serialization.
