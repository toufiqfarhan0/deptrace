alex: Heads up — running into a weird combo of typing + runtime leak with the Async SDK contextmanager when used in FastAPI background tasks. Minimal repro below, hangs sometimes and emits ResourceWarning about pending tasks.

alex: repro:```python
# repro.py
from redwood import AsyncInferenceClient
import asyncio

async def bg():
    async with AsyncInferenceClient() as c:
        await c.generate("hi")

async def main():
    loop = asyncio.get_event_loop()
    loop.create_task(bg())
    await asyncio.sleep(0.2)

asyncio.run(main())
```

jake: tag me @alex, thanks for the repro. My hunch: AsyncInferenceClient (wrapping httpx.AsyncClient) is binding to the loop at __aenter__ and when it's later awaited from a different loop/context it leaves pending tasks. Also saw mypy errors about __aenter__ return type being Any which hides typing issues.

priya: any quick workaround?

jake: try avoiding context manager across loop boundaries. e.g. create the client and run its lifecycle on the same running loop, or explicitly close it in the same context:```python
client = AsyncInferenceClient()
await client.__aenter__()
# kick it off from same loop
await client.generate(...)
await client.aclose()
```
It's ugly but helps until we patch.
