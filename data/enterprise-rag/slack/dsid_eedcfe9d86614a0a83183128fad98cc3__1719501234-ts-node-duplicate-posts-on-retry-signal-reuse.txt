eng_chris: ok that undici version is a little old for Node 20's global fetch changes. Two plausible causes: 1) AbortController signal reuse across retries can interact poorly with undici's internal retry/backoff leading to aborted native sockets but the SDK still attempting an application-level retry that results in duplicate downstream POSTs. 2) Missing idempotency on POSTs — the safest short-term mitigation is to require callers to pass an idempotency key for mutating endpoints.
devex_sam: short-term workaround: disable automatic retries for that endpoint and do explicit retry logic with per-attempt AbortController and a jittered backoff. Example:
```
// per-request controller
function send(item) {
  const controller = new AbortController();
  return client.createCompletion({input: item}, {signal: controller.signal, retries: 0});
}
```
devex_sam: also set header `Idempotency-Key` so the server can dedupe.
customer_matt: tried disabling retries (retries: 0) and creating a new AbortController per request — appears to stop duplicates in their small test. Still want a permanent fix.
eng_chris: filing an internal bug — looks like the SDK's retry wrapper is reusing the same AbortSignal across attempts in v1.3.0 which is wrong. We'll patch to create a fresh signal per attempt and ensure undici request objects are properly aborted/cancelled before emitting another attempt.
