sam: Quick q — do we want queue topology to be tightly coupled to admission policy or expose a decoupled surface API? thinking about continuous-batcher router complexity.

cheng: For latency SLOs coupling helps pack similar length/payloads which improves kernel utilization, but it hurts fairness when tenant work shapes change quickly.

alex: Also coupling increases state churn during deploys. If admission logic changes, we end up migrating queue state across many workers. seen that blow up in staging.

sam: yeah saw that. the race is in the migration handshake between old admission and new queue-owner.

maria: rough proposal: keep admission decisions pluggable (PolicyPlugin) but return a compact stable queue_id that maps to a physical queue. decoupled API but stable ids so operators can reason about state.

cheng: sounds neat. indirection costs an extra lookup per request though — any numbers?

alex: extra lookup is tiny vs GPU kernel time. we measured ~200ns in a prior prototype. the bigger cost is complexity of cache invalidation / TTL.

sam: if we memoize mapping at the connection level we avoid repeated lookups, but eviction/migration becomes tricky — need TTL + metrics to avoid stale pins.

maria: agreed. Also we should surface observability: expose mapping metric (queue_id -> admission_policy_version) and a tag for sticky vs ephemeral. otherwise debugging is awful.

cheng: a downside: tight coupling naturally gives KV-cache affinity (same queue => same KV shard and warmer KV hits). decoupled routing would need separate KV-affinity plumbing.

alex: yeah, decoupled + naive KV would regress cold-starts. we could implement a kv-affinity layer that consults queue_id mapping. more plumbing but keeps logical separation.

sam: what about a hybrid: default decoupled model for flexibility, plus an optional "sticky queues" fast-path for heavy tenants where we keep queue and admission coupled for affinity? feature-flagged.

maria: i like hybrid. rollout plan idea: opt-in sticky queues for top tenants first, measure improvement. API suggestion for router surface:

maria: ```

Router -> PolicyPlugin -> queue_id
```
