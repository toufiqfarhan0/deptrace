maria: Quick sync about egress IP strategy for Private endpoints. Spike results: per-tenant NAT is safest for isolation but costs and EIP exhaustion are real. Need to choose a long-term pattern before we build more automation.
joel: Yep. Can we list current options concisely?
maria: Options on table: 1) Per-tenant dedicated NAT (one EIP per tenant or small pool) 2) Shared NAT with port-preserving mapping + per-tenant DNAT ranges 3) Ephemeral egress agents that attach/borrow EIPs from a pool per-agent lifetime 4) Regional relay that SNATs at a central relay (adds an extra hop)
anna: Relay reduces per-customer IPs and simplifies certs, but it adds latency. Our tail SLOs for <100ms are tight on some workloads. Need data from relay spike.
devon: Per-tenant NAT is operationally simple for audit and whitelists, but address exhaustion + cost at scale. We also need clear rotation/replace plan for EIPs.
leo-arch: Also watch migrations: overlapping customer CIDRs. If we SNAT away source IP we break license whitelists and some carrier-grade NAT checks. Some customers require source IP preservation.
shreyas: Proposal: hybrid. Default to shared NAT (cheap). Offer on-demand dedicated EIP for tenants that opt-in or have preserve-ip needs. Ephemeral agents handle most traffic and advertise EIPs.
maria: We discussed this in RFC but didn't finalize allocation lifecycle (when to allocate, TTL, release).
joel: Concrete flow suggestion: allocate dedicated EIP on first preserve-ip request. Record owner in CP DB. Idle TTL: 7 days then release. Tag allocations with rotation id for audits.
anna: 7d seems long for churny dev/test tenants. Suggest 24h idle TTL for non-enterprise, 7d for enterprise.
devon: Ops: how do we ensure deterministic routing and failover from VPC endpoints to ephemeral agents?
leo-arch: Agent model: each Private endpoint runs an egress agent that registers to CP over mTLS. Agent announces available EIPs, capacity. CP programs a Regional NLB (or IPVS) to forward flows to healthy agents. Fallback: regional relay SNAT if no agent available.
maria: Example register payload (agent -> CP):
```
POST /v1/agents/register
{
  "agent_id": "ep-01-abc",
  "region": "us-east-1",
  "eips": ["3.120.45.12","3.120.45.13"],
  "capacity": 250,
  "version": "ep-agent/1.5.0"
}
```
CP verifies client cert, stores binding, tags pool.
shreyas: Eviction rules: when agent capacity exhausted, evict by oldest-lease, then by least-used tenant. Also support explicit admin preemption for emergencies.
anna: Observability: token-level tagging so we map tokens/requests -> eip. Billing needs per-eip attribution and noisy-tenant detection. Dashboard per-eip and alert when token-stall rates spike.
devon: Automation: reconciliation job every 5m to ensure EIP pool <-> allocations; raise pager if pool below threshold; dry-run failover weekly to validated relay path.
joel: Security: prevent EIP->tenant mapping leaks. NAT logs keep only EIP + hashed-tenant-id in common logs; full mapping in restricted audit store with decryption access controls. Also rotate hashes when tenants rotate credentials.
leo-arch: Migration plan: default everyone to shared NAT. Provide opt-in migration window + migration automation for enterprises requesting dedicated EIPs. Offer runbook and scheduled cutover to avoid split-brain.
maria: Decision proposal (for RFC): hybrid model: shared NAT default; on-demand dedicated EIP for preserve-ip customers; TTLs: 24h idle for dev/test, 7d for enterprise; ephemeral egress agents as default dataplane with regional relay fallback; ops automation + dashboards as above.
