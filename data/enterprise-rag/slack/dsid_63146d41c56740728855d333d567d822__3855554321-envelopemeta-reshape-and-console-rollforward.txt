kevin: Heads-up — I want to reshape how we store envelope-level routing/quotas for console/analytics. Opening a quick design thread before a PR.

kevin: Short: introduce envelope_meta (jsonb) on analytics.events_envelope. Move route_id, quota_profile_id, client_region into that blob instead of separate columns. Rationale: fewer schema churns as we add fields and allows a single GIN index for many access patterns. Also lets us ship new metadata without table migrations each time.
maria: Concern: console and some dashboards expect route_* columns (denormalized). If we remove them overnight we break queries/alerts. We need a read-adapter or compatibility layer.
kevin: Exactly — plan is dual-write + read-adapter. Steps I propose:
- add envelope_meta jsonb NULL and index
- deploy read-adapter in console/api that maps legacy fields to envelope_meta on read
- enable dual-write at ingest (feature-flagged) for 14 days
- run async backfill and monitor 
- once stable, remove legacy columns after TTL window

SQL snippet for migration (proto):
```sql
ALTER TABLE analytics.events_envelope ADD COLUMN envelope_meta jsonb NULL;
-- GIN for flexible queries across keys
CREATE INDEX IF NOT EXISTS idx_events_envelope_meta_gin ON analytics.events_envelope USING gin (envelope_meta jsonb_path_ops);
-- lightweight btree for the common string lookup we use in dashboards
CREATE INDEX IF NOT EXISTS idx_events_envelope_meta_quota ON analytics.events_envelope ((envelope_meta->>'quota_profile_id'));
```
