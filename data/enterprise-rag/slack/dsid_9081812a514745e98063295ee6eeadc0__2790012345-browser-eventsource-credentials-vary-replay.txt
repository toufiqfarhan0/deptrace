frontend_maya: Safari + ServiceWorker often interacts weirdly with SSE polyfills. If the SW returns a cached Response object for the same request, it can hand a body that's already been partially read. Are you doing `caches.match(event.request)` and returning that directly?

customer_ray: We thought caching helps cold starts but maybe it's reusing streamed responses.

eng_sre_dan: A few likely culprits combined:
- CDN caching SSE endpoints (shouldn't cache streaming responses) -> other clients get cached partial response.
- Missing CORS credentials headers -> browser might drop or block credentials-based streams in some browsers.
- SW returning a cached Response that was a streaming Response (bodies are single-use) -> subsequent consumers see truncated body.

eng_sre_dan: Immediate checks: add `Cache-Control: no-store` or `Cache-Control: private, no-cache` for SSE endpoints; include `Vary: Cookie, Authorization` if you must cache select variants; ensure `Access-Control-Allow-Credentials: true` and `Access-Control-Allow-Origin` is the specific origin, not `*`.
