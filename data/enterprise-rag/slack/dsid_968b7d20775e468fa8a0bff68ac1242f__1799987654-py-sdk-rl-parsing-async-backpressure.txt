alex: Heads-up — found a surprising behavior in the py-sdk async client when we hit 429s with the quota headers during our stress runs.
jamie: repro steps?
alex: Load test hitting /v1/generate concurrently (200 coroutines). When upstream replies 429 with a multi-resource header, our client ends up treating it as a single global bucket and serializes everything, which blows latency.
alex: Example header we saw (copied from logs from quota-bot):
quota-bot: HTTP/1.1 429 Too Many Requests
X-RedQuotas: tokens=150/second;embeddings=10/minute;retry_after=3
sara: oof. I thought we already supported parsing multiple resource entries? looks like the code flattens by splitting on comma only.
alex: Exactly. Current parser is roughly:
```
def _parse_quota(header: str) -> Dict[str, int]:
    # naive: split on "," then take last token => overwrites earlier entries
    pairs = header.split(",")
    k, v = pairs[-1].split("=")
    return {k: int(v.split("/")[0])}
```
alex: So when header uses semicolons (or mixed separators) and multiple resources, we only keep the last entry (embeddings)
jamie: That explains the observed behavior. Under concurrency we back off using embeddings rate which is much lower, so tokens requests wait and pipeline stalls.
sara: Proposed fixes:
- robust header parser that accepts ",", ";" and whitespace as separators
- return a mapping of resource -> (limit, window_seconds, retry_after)
- make the client-side throttle accept per-resource token costs and multi-bucket coordination (e.g., token requests check all relevant buckets)
jamie: For async, we should avoid a single global asyncio.Semaphore. Instead, implement per-resource AsyncRateLimiter objects with an async acquire(cost: int, resource: str) API. That lets callers concurrently use different resources without stepping on each other.
alex: Agree. Also typing updates: RateLimiter should expose a Protocol for sync/async compatibility, and our py-sdk public types should be generics so users can pass typed resource names (e.g., Literal["tokens","embeddings"]).
alex: Quick sketch:
```
class AsyncRateLimiter(Protocol):
    async def acquire(self, resource: str, cost: int = 1) -> None: ...
    def release(self, resource: str, cost: int = 1) -> None: ...
```
jamie: Implementation notes:
- parse headers into a list of buckets: [(resource, limit_per_window, window_s)]
- keep counters with monotonic timestamps and atomic updates (async locks per resource)
- when server returns Retry-After, map it to temporary blocked state for that resource
alex: Also we need to be careful in the retry middleware: currently we sleep on Retry-After but still add requests into the global queue. Instead, on 429 for resource R we should inform the limiter to block R for retry_after seconds so subsequent requests for R are throttled locally without queuing upstream.
