alex_g: our canonicalize produced different ordering for tools in some clients which exploded misses.

maria_s: can we normalize tool order and strip system trailing newlines? that should be cheap.

alex_g: did that in a branch + pinned tokenizer version in the key to tok:v2. also added unicode normalize NFC and collapse whitespace. quick pseudo: 
```
def canonicalize_prompt(prompt, system='', tool_meta=None, tok_version='v2'):
    p = prompt.strip()
    p = re.sub(r'\\s+', ' ', p)
    p = unicodedata.normalize('NFC', p)
    key = f"{tok_version}|{system.strip()}|{p}"
    if tool_meta:
        key += f"|tools:{','.join(sorted(tool_meta))}"
    return hashlib.sha256(key.encode()).hexdigest()
```

jonah_r: nice. did that move the needle?

alex_g: yes — on our canary traffic hit-rate for short prompts jumped from 58% -> 79% and median latency stayed ~same. CPU on kv_lookup dropped ~28%.

sasha_t: any regressions? we changed kernel selection too which originally improved tail latency. did canonicalization undo that?

alex_g: good call. kernel_select still helps p99 for long contexts. problem was the coupling: kernel bump + changed batching heuristics increased batch size, causing more partial-prefix evictions during aggressive warmup. when canonicalization reduced misses, eviction pressure normalized.

maria_s: what about warmup strategy? we saw a spike in cache churn at start-of-epoch with bursty traffic.

alex_g: implemented a staged warmup ramp: small steady prefix-only warmup for first 30s, then gradual batch size increase over 3 mins, plus a fallback to legacy kernel if miss-rate > 40% for 60s.

jonah_r: can you share the scheduler pseudocode?

alex_g: sure — simplified: 
```
# warmup scheduler
state = 'ramp_small'
start = now()
while now() - start < 180:
    if state == 'ramp_small':
        batch_target = 1
        if now() - start > 30:
            state = 'ramp_medium'
    elif state == 'ramp_medium':
        batch_target = 4
        if miss_rate(window=60) < 0.25:
            state = 'ramp_full'
    else:
        batch_target = conf.max_batch
    if miss_rate(window=60) > 0.4:
        kernel = 'legacy'
    else:
        kernel = 'opt-v2'
    apply(batch_target, kernel)
    sleep(2)
```

maria_s: looks sensible. any cost impact?

alex_g: trivial on steady state. short-term warmup extends some requests hitting CPU but reduces re-gen costs. net cost down ~6% for the customer sample.
