design

mira: Quick design ping — pushing a small IA change to consolidate workspace nav. Proposal: collapse misc left-panel groups into 3 zones: Workspaces, Models & Assets, Insights. Goal is fewer cognitive hops for new users and clearer deep-linking semantics. Sharing sketches + route contract thoughts below.

mira: Example deep links we want to guarantee (canonical):
```
/app/ws/:wsId
/app/ws/:wsId/models/:modelId
/app/ws/:wsId/models/:modelId/settings
/app/ws/:wsId/insights/requests?range=30d
```

mira: Questions:
- Should breadcrumbs reflect every level (Workspace > Models > Model) or be condensed (Workspace • Model)?
- Do we want path-based history (/app/...) only or allow hash for client-side nav on some panes?
- Accessibility: keyboard jump targets for the three zones and aria-current contract?

jon: quick take — path-based only. Hash routing adds unexpected back/forward behavior and breaks copy/pastes. Keep canonical pathname and pushHistory.

priya: Agreement from PM side: path-based also helps analytics and SSO deep-linking from emails. We need a migration plan for existing saved links. Can we support a 1:1 redirect map?

mira: Yes — plan is server-side redirects for legacy hashes for 6 months + console banner to surface changed URLs.

sam: A11y notes:
- Ensure each zone header is a real landmark (role="navigation" aria-label="Workspaces") so screen readers can skip.
- Breadcrumbs should use aria-current="page" on the last item.
- When collapsing groups, preserve focus and announce via live region if the active item moves.

sam: Also prefer explicit focusable separators (tab stops) between the three zones. Avoid relying purely on visual spacing.

jon: Implementation notes:
- We'll treat the left panel as 3 sections with aria-labelledby and section-level <ul> lists.
- Router change is mostly moving from our legacy hash router to react-router path routes. Small snippet: 
```
<Routes>
  <Route path="/app/ws/:wsId" element={<Workspace />}>
    <Route path="models/:modelId" element={<ModelPage />} />
    <Route path="insights/:tab" element={<Insights />} />
  </Route>
</Routes>
```

jon: Will need a migration shim for `/#/ws/:id/...` -> `/app/ws/:id/...` that runs on first load and does a 301-ish redirect.

lee: Copy tweak suggestion: change sidebar label `Models & Assets` -> `Model registry`. Helps reduce ambiguity for non-ML folks. Maybe keep secondary label for assets in tooltip.

mira: Like that. Also thinking breadcrumb text: prefer short nouns — `WorkspaceName > ModelName` rather than `WorkspaceName > Models > ModelName` to cut repeated nouns. But keep the full path in the URL for clarity.

priya: Can we add a little migration checklist for customers? i.e., saved dashboard links, bookmarks, third-party integrations. Assign to Solutions/Docs to email top 20 active customers.

mira: I'll draft messaging.

jon: Accessibility + keyboard: I'll wire arrow key navigation inside the left panel and make Enter open deep links (and also open with Space). Need design confirmation on focus ring styling.

mira: Use 2px high-contrast outline — matches console focus tokens.

sam: Add requirement: screen reader should hear "Workspace X, region, Models, active" when focus lands on the models header. Live region: subtle polite update when route redirects happen.

priya: Rollout plan: canary to 10% of sessions in staging, feature flag to toggle IA change per workspace. If metrics (click depth, session time) regress >10% we rollback.
