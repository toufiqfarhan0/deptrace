Ivy: Hi all, Ivy here (first day!). Trying to follow the dotfiles flake setup (Nix + flakes) instead of the usual bootstrap. asdf installs fail for Python/node with missing openssl headers. Brew is installed but I wanted to keep Nix-managed packages. Any recommended approach so builds succeed without ripping out Nix?

marc: welcome Ivy! :wave: we have a couple folks using Nix. Short answer: asdf build scripts expect libraries available in the build environment. If you rely solely on Nix, you need the build inputs (openssl, zlib, readline) present in the shell where `asdf install` runs.

jules: if you're using the flake-based dev shell, add `openssl`, `pkgconfig`, `zlib`, `readline` to `devShell.packages`. Example in flake.nix: `devShells.default = pkgs.mkShell { buildInputs = [ pkgs.openssl pkgs.zlib pkgs.readline pkgs.pkgconfig ]; }`. Then `nix develop` will provide headers.

Ivy: ah got it — I was running asdf from my regular login shell so the Nix shell packages weren't visible. Is it bad to mix brew and nix?

marc: mixing is fine but be explicit. If you use brew openssl at /opt/homebrew, export build flags so asdf uses it: `export LDFLAGS="-L/opt/homebrew/opt/openssl@1.1/lib"` `export CPPFLAGS="-I/opt/homebrew/opt/openssl@1.1/include"` `export PKG_CONFIG_PATH="/opt/homebrew/opt/openssl@1.1/lib/pkgconfig"`. But if you're in `nix develop`, let Nix provide the libs instead to keep reproducibility.

jules: another tip: some folks wrap asdf install in the nix shell: `nix develop --command asdf install python 3.11.6` so the compiler sees Nix-provided headers. Also ensure `PATH` doesn't point to a different openssl from brew when you expect Nix ones.

Ivy: thanks! One follow-up: the dotfiles flake symlinks a `.shell_env` that points to nix profile paths. Should I source that in ~/.zshrc or let nix manage it?

nathan: for Nix users we keep a small shim: source `~/.shell_env` from ~/.zshrc only if not in a nix shell. When in `nix develop` the shell env is ephemeral. So add `if [ -f ~/.shell_env ] && [ -z "$IN_NIX_SHELL" ]; then source ~/.shell_env; fi` to your rc file. That avoids conflicting libs during builds.

Ivy: node plugin also complained about GPG import when adding nodejs plugin via asdf. Does Nix provide gpg/pinentry?
