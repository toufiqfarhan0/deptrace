dara.new: hi team — first week, quick question about secrets onboarding. I need to bootstrap my service (ingest-stack) with a DB password and also request a CMK for encrypting S3 backups. what's the exact flow, who signs off, and any tips for the initial secret-zero?

maria.devex: Welcome Dara! :wave: Flow summary: 1) Open a secret_request in #platform-requests with the template (include envs and approvers). 2) Infra provisions per-env Vault policies for the service principal. 3) For CMK creation/grants, include cross-project IAM details; security + infra must approve. Secret-zero: create using a short-lived manual secret stored in Vault KV then immediately rotate to dynamic creds where possible.

kevin.security: Adding security notes: a) For prod CMKs you must list a business approver (PM/eng lead) + a security approver (me or my delegate). b) No wildcard policies; use per-service, per-env paths. c) Secret-zero should never be checked into code or CI logs. Use encrypted input (transit) or upload via our one-time secret uploader (see infra-shared).

dara.new: what's the secret_request template look like? also how do I indicate the service principal name in the ticket?

maria.devex: Template (paste in ticket body):

```
secret_request:
  requester: dara.new
  service: ingest-stack
  envs: [dev, staging, prod]
  vault_paths:
    - secret/data/ingest-stack/dev: read
    - secret/data/ingest-stack/staging: read
    - secret/data/ingest-stack/prod: read
  kms_key: projects/redwood-prod/locations/global/keyRings/backups/cryptoKeys/ingest-cmk
  service_principal: svc-ingest-stack@redwood-prod.iam.gserviceaccount.com
  approver: @kevin.security
  reason: runtime DB creds for ingest + encrypting daily backups
```

maria.devex: Include the exact service principal email for GCP/AWS principal binding. If you need an IAM role that spans projects, call that out and attach the short RFC in the ticket.

kevin.security: Rotation basics: use Vault DB dynamic creds where supported (auto TTL + rotation). For long-lived secrets (rare), default rotation is 90 days; indicate owner and rotation cadence in the ticket. CMKs: recommend annual rotation unless the workload requires otherwise. For emergency compromise follow the incident runbook.
