rachael: Quick brain dump — thinking about a lightweight "probe + stub" path for v2->v3 surface migration instead of a heavy gateway shim. Goal: minimal latency impact, explicit opt-in, safe passive sniffing for a short window.

ton y: I like keeping things small. Main wins: easier rollback, fewer moving parts. Main risks: mis-detection and edge-case rewrites.

omar: Agreed. If we do passive sniffing we must be conservative. Prefer explicit header `X-Client-Version: 2` for determinism, but allow passive detection for a 2-week grace window.

sid: Infra note — stub adapters can be hosted on edge proxies (nginx/envoy filters) to avoid extra hop. Need to watch connection pooling and cache key semantics.

mei: From quality side: add a small eval harness — sample 500 canonical prompts, compare outputs before/after rewrite, track semantic diffs. Stop rollout on regression.

rachael: Proposed probe pseudo logic:
```
if request.headers['X-Client-Version'] == '2':
  route = adapter_v2_to_v3
else if payload.shape == EXPECTED_V2_SHAPE and rand() < PASSIVE_PROBE_RATE:
  mark.metric('probe.passive_detect')
  route = adapter_v2_to_v3
else
  route = native_v3
```
Keep PASSIVE_PROBE_RATE small (0.1-1%) initially. Log original+rewritten payloads to an audit queue (PII redaction).
