lev: thinking out loud — can we infer routing hints from a short session tag header (x-rd-session) instead of relying on UA heuristics?

maria: curious what you mean by 'session tag' — opaque id or structured?

lev: structured, small (~40 chars). contains tenant id, env hint, and optional experiment flag. e.g. `tenant=acme;env=prod;exp=canary` encoded and signed.

aj: signed how? we already have x-auth-token and tenant header precedence rules. adding another signed header increases complexity. :thinking_face:

lev: idea: HMAC with key per routing-controller, rotates quarterly. signature appended as `sig=` portion of header. router verifies before trusting.

tom: verification at edge is fine, but who mints these session tags? edge gateway or auth service?

maria: auth service seems logical — it already knows tenant mapping and user-level quotas. but that means auth must be in the critical path for every request (latency risk).

aj: could mint lazily: auth service mints at login/first call, then client caches tag. router checks signature only when tag present; fallback to existing UA/claim heuristics if missing.

nina: telemetry question — if we route by session tag, we need to capture tag parts (tenant, exp) in our traces and billing breakouts. that'll change console dashboards. we should surface which routing decision was used: TAG vs UA vs AUTH.

lev: agreed. minimal change: add `x-rd-routing-evidence: tag|ua|auth` as a router-internal header for downstream observability (not user-visible).

sre-bot: deploy note: adding verification will touch edge-workers and gateway lambda. recommend feature flag rollout with canary in us-west-2 first.

maria: UX for rollout in console? product wants a toggle per tenant: opt-in tag-based routing so enterprise customers can try without global switch.

aj: implementation sketch (pseudo):
```
if header_exists(x-rd-session) and verify_sig(x-rd-session):
  parsed = parse(x-rd-session)
  choose_route(parsed.tenant, parsed.env, parsed.exp)
  set_header(x-rd-routing-evidence, "tag")
else if header_exists(x-tenant-override):
  // existing precedence
  set_header(x-rd-routing-evidence, "auth")
else:
  infer_route_from_ua()
  set_header(x-rd-routing-evidence, "ua")
```

lev: also important: quota accounting. If tag says tenant=T, we must attribute usage to T even if auth token is tied to user. need audit trail and fallback safety to prevent billing spoofing.

maria: so require signed tag and ensure auth service only mints tags for tenants it can vouch for. plus add logging for signature failures and mismatches (tag tenant != auth tenant).

tom: security edge case: public clients might try to forge tags. signature mitigates but we should rate-limit signature verification attempts and surface spikes to SRE.
