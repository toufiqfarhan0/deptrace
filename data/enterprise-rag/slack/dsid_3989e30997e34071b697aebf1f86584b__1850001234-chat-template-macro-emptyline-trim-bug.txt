Ana (ml): heads-up — onboarding HF model 'orca-mini-custom' hit a weird chat_template conversion issue when we convert the jinja template to Redwood prompt format.
Ana (ml): minimal repro below:
Ana (ml): ```jinja
{% macro msg(m) -%}
{% if m.system_text %}
<|system|> {{ m.system_text }}
{% endif %}
<|role|> {{ m.role }}
{{ m.content }}
{%- endmacro %}

{{ msg(metadata) }}
{{ for m in messages }}
{{ msg(m) }}
{{ endfor }}
```
Ana (ml): when metadata.system_text is empty the converter seems to collapse the next role delimiter into the previous line, resulting in the first assistant message being concatenated with the user prompt (no explicit role token). Repro on local converter v0.9.1.
Ben (infra): can you paste the actual rendered string that goes to the runtime?
Ana (ml): sure — rendered during conversion we expect something like:
Ana (ml): ```text
<|system|>
<|role|> system
System preamble
<|role|> user
User prompt
<|role|> assistant
Assistant start
```
Ana (ml): but observed output is:
Ana (ml): ```text
<|role|> system
System preamble
<|role|> user
User Prompt<|role|> assistant
Assistant start
```
Ana (ml): missing the explicit system token line and a newline before the assistant token.
Chris (mlops): ugh — this looks like our whitespace-trimming pass in the converter that aggressively strips empty-block newlines. I've seen that bite quantized runs where tokenization changes a lot.
Chris (mlops): on a quick eval, this shifts the token boundary and in int8 quant we get ~2.4% regression on the instruction-following bench — small but consistent.
