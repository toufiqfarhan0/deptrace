maya: Heads-up — I'm proposing a 'metered lease' model for per-org rate limits to combine RPM/TPM with concurrency caps. Idea is leases that represent concurrent slots which decay after request completion or TTL.

jamal: quick TL;DR? how's this different from burst credits + concurrency today?

sree: +1 on summary. curious about enforcement: do we enforce RPM/TPM and leases atomically or sequentially?

maya: TL;DR: 1) keep RPM/TPM for long-term smoothing, 2) allocate short-lived leases for concurrency so spike handling is local and cheap, 3) leases consume a light-weight bucket that refills slowly (burst budget) so you can have short bursts without violating RPM.

eli: So basically: request flow: check lease availability -> take lease -> check RPM/TPM global counters -> serve. If RPM exhausted then lease gets cancelled and request fails or gets queued?

maya: Exactly. Preference is to prefer graceful degrade: if RPM exhausted but lease available, either 1) accept but route to lower-throughput path (lower qps model variant) or 2) accept with reduced token budget and tag telemetry. Fallback policy pluggable per org.

ana: (typo: ana) we need concrete numbers to simulate. What TTL for leases? 5s? 30s?

sree: I like 3s-10s depending on model latency. For chat short paths TTL ~5s. For embeddings longer TTL maybe 20s. Lease TTL should be derived from p50/p95 latency distributions per model.

jamal: How do we avoid lease hoarding by stuck requests? need reliable cleanup + heartbeat.

maya: require client to return lease on finish (best-effort). server enforces TTL and also probes active tasks. If health-check shows stuck goroutine, force release and increment stuck counter for org. Ops alert on high stuck ratio.

eli: UX: console should show "active leases", "leased vs available", and a sparkline of lease acquisition latency + lease timeouts. Also expose per-org policy: lease size, refill rate (burst window), TTL, fallback policy.

ana: Telemetry: we need per-request tags: lease_taken=true/false, lease_ttl, lease_age_on_release, fallback_triggered, fallback_reason. Those should feed the per-route cost breakdown and QoS dashboards.

jamal: enforcement implementation detail: do we place leases in the router (edge) or at runtime? concerns: consistent counting across replicas.

sree: recommendation: place lease fast-path at edge router (consistent hashing per org to single counter shard) to avoid extra hop. RPM/TPM counters still global and use our current distributed counter with approximate allowances. If router can’t reach counter, allow lease but mark fallthrough.

eli: race condition: two routers could hand out leases simultaneously if TTL crossing and sync lag. We should accept small overprovisioning (configurable safety buffer).

maya: Policy knobs in console: safety_buffer_percentage, lease_ttl_ms, burst_refill_rate (tokens/sec), max_concurrent_leases. Default conservative values to avoid overcommit.

ana: rollout plan: start as opt-in per org -> lab test with internal tenants -> expose telemetry -> gradual default on for free-tier with low limits.
