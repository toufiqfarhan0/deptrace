bijoy: i've seen this. Next() is blocking on an internal recv channel. when handshake fails we do an internal state reset but we don't always close the recv channel in the failure path.

sam: that's a UX footgun for onboarding. sampleapp uses a naive `for { tok, err := gen.Next(); if err != nil { break } ... }` pattern. without a context-aware pull API it's hard to cancel cleanly from the app.

ana: exact snippet in examples/generator/main.go around line ~142.

ryan: options: 1) add `Next(ctx context.Context) (Token, error)` and keep `Next()` for compatibility; 2) keep API but document that caller must call `gen.Close()` on auth events; 3) SDK auto-closes iterator on handshake fatal. pros/cons?

bijoy: 3) is surprising: SDK auto-closing could race with consumer cleanup logic. 2) is low lift but brittle. 1) is nicer ergonomically and matches other libs (python/js have ctx-like cancel semantics).

ana: i'll paste the minimal repro and a heap trace. also adding a tiny wrapper pattern we used as a temporary workaround:
```
ctx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
resCh := make(chan error, 1)

select {
case <-ctx.Done(): gen.Close()
case err := <-resCh: _ = err
}
```
