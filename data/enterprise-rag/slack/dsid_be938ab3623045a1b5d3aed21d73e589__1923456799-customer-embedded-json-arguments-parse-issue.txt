lee_engineer: Repro'd locally with same payload. Root cause: our parser expects `arguments` to be a JSON object/array. The customer sent a string that contains JSON (stringified JSON). On our side we call JSON.parse once on the `arguments` value; when it's a string containing braces the parse of the outer body succeeds but then we try to interpret the inner string as raw JSON and it fails because escaping was lost.

lee_engineer: Short-term customer workaround: send `arguments` as a true JSON object rather than embedding JSON inside a string. Example working body: 
```
"function_call": { "name": "order-processor", "arguments": { "order": { "items": [{ "sku": "ABC123", "qty": 2 }] }, "meta": { "source": "mobile" } } }
```
OR double-escape the inner string so the transport yields a valid JSON string on our side (ugly).

tom_prod_owner: Many clients embed JSON blobs in strings for logs/payloads. We should be tolerant by default, but careful about semantics and safety.

lee_engineer: Proposed fix: if parsed value is a string and it looks like JSON (trim starts with '{' or '['), attempt a second JSON.parse inside try/catch. Add max length guard (skip double-parse if string > 100KB) to avoid CPU DoS.
