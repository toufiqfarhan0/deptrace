oli: also check wrangler's packaging step — it zips files from the project root. If the pnpm virtual store files are symlinked outside the project dir, the deploy environment won't have them. We saw this before. For sample-app CI we solved it by running `pnpm pack` for the SDK and then `npm install` inside the app's CI build to avoid symlink references. Ugly but effective.

samir: DX fix for SDKs: publish a tiny flat layout so consumers never need to follow deep internal paths. Example: add `index.mjs` at package root that re-exports dist, and flatten exports to `".": {"import":"./index.mjs","require":"./dist/cjs/index.cjs.js"}`. That plus shipping d.ts at root (or top-level types field) prevents TSC/bundlers from chasing symlinks.

maya: We experimented with two approaches: 1) recommend `nodeLinker=node-modules` for CI to get a regular node_modules layout, 2) SDK-side: root ESM shim + simpler exports. Both worked; root shim is less friction for customers.
