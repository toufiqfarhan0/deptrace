alex (infra): Quick RFC follow-up idea — swapless overlay patch proxy for air-gapped installs.
alex (infra): Problem: customers want smaller, auditable updates without swapping base images or rebooting.
alex (infra): Proposal: deliver signed patch bundles that mount as an overlay on top of sealed image; activation is an operator signal (no image swap).
sam (eng-runtime): How do we guarantee binary compatibility when we layer a new server binary over old libs?
alex (infra): Two parts: 1) patch manifests include constrained compatibility matrix (ABI tags + min lib versions). 2) runtime compatibility check runs pre-activation and fails fast.
marie (security): Need an offline verification chain. We can't rely on live key server in airgap.
alex (infra): Agreed. Each bundle will include a compact replay log and a chain of signatures. Operator provides KMS anchor during initial bootstrap. Verification is offline: verify(manifest) -> verify(replay) -> verify(signature).
jordan (eng-sre): If overlay apply fails mid-apply, how do we avoid partial state?
alex (infra): We stage patches to a staging overlay snapshot and only flip activation when all integrity checks pass. If failure, we drop the staging overlay. No rewrite of base image.
