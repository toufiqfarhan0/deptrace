Jenna (Design): Quick design check-in: proposing a typed-confirm pattern for org token revokes (to reduce accidental outages). Figma: https://www.figma.com/file/zyxw4321/tokens-typed-confirm. Main concerns: friction vs safety, copy, and keyboard discoverability. Thoughts?

Ravi (Eng): Typed-confirm plus checkbox OK from infra perspective. We'll need the exact confirm string to validate server-side. Also suggest fallback undo window (10s) with soft-revoke.

Maya (Security): Strong +1 for typed confirm on org tokens. Suggested text: \"Type the token name to confirm revocation\" and require checkbox: \"I understand revoking affects services\". For extremely high-impact tokens (admin.*), require exact match and audit log tag `revoke:typed_confirm`.

Sam (A11y): Accessibility notes: the confirm input must be focused when the dialog opens. Use `aria-describedby` referencing the irreversible warning. Example snippet:
```html
<div role=\"dialog\" aria-modal=\"true\" aria-labelledby=\"revoke-title\">\n  <p id=\"revoke-desc\">Irreversible: this will stop all apps using this token.</p>\n  <label for=\"confirm\">Type token name to confirm</label>\n  <input id=\"confirm\" aria-describedby=\"revoke-desc\" />\n</div>
```
Also ensure the dialog announces the list of affected services if present.

Ava (PM): UX tradeoff: we want protection but not too many clicks for developers doing maintenance. Proposal: only show typed-confirm for org-level and admin-scoped tokens. Personal tokens get the checkbox + snackbar undo.

Tess (QA): From testing sessions, users understood typed confirm if it's clearly framed. Add positive default focus on the input and ensure keyboard flow: Esc closes, Tab cycles within dialog, and button only enables after exact match. I'll add automated tests.
