nina: New hire ran into a CF Workers quickstart failure. Build ok but deploy: 'ReferenceError: process is not defined' and later 'Error: Cannot find module "net"'. We only call fetch + jwt verify. Any quick pointers?

omar: Most likely a transitive dependency pulling in node builtins (buffer, net, fs). Which jwt lib?

nina: using jwt-lite; bundle shows buffer imported by a helper.

leo: Two approaches: replace with a web-first helper or publish a tiny opt-in shim that provides clear stubs and web-crypto helpers. For example: `@redwood/inference-edge-shims` exporting `verifyJwt`, `safeFetchAuth`, and `nodeBuiltinStubs`.

leo: Example guard for WebCrypto:
```js
export function assertImportKey(){
  if (typeof globalThis.crypto?.subtle?.importKey !== 'function'){
    throw new Error('WebCrypto importKey not available in this runtime. See https://go.redwood.dev/edge-crypto')
  }
}
```

omar: For bundlers: set esbuild target to `service-worker` (or wrangler target) to avoid auto-polyfills. Also use conditional exports in packages so worker builds pick worker-specific entrypoints.

nina: TS users hit "cannot find module" when shim lacks d.ts. So add `types` in package.json and ship `index.d.ts`. Also recommend tsconfig snippets: `{"lib":["es2021","webworker"],"moduleResolution":"bundler","skipLibCheck":true}`.

leo: Auth/retry nuance: in Workers do a one-time token refresh with a global Promise to avoid thundering: `globalThis.__RW_REFRESH = globalThis.__RW_REFRESH || refresh()` pattern. And retries: single refresh + up to 2 exponential backoffs with jitter for other transient errors.
