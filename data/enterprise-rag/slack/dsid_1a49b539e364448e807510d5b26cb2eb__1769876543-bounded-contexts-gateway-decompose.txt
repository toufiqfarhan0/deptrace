maria.c: Proposed minimal proto snippet for the stream:

```proto
message InferenceRequest {
  string request_id = 1;
  repeated bytes prompt_chunks = 2;
  map<string,string> metadata = 3;
}
message InferenceChunk {
  string request_id = 1;
  bytes token = 2;
  bool end_of_stream = 3;
}
service InferenceService {
  rpc StreamInfer(stream InferenceRequest) returns (stream InferenceChunk);
}
```

leo: That looks good. Keep metadata small. Also: include client-side deadline and server-side per-token budget so we can early-abort expensive requests.

jordan: Migration concerns: lots of internal libraries call the current monolith clients. We should implement a compatibility shim that exposes the old client surface but proxies to gateway. That gives time to refactor callers.

olivia: Tech debt paydown: the legacy session store is tangled with auth code. We should extract a thin SessionService (stateless if possible) and back it with a lightweight Redis TTL table. That makes runtime scaling simpler.

maria.c: Rollout plan sketch: 1) implement gateway + runtime prototypes behind feature flag in staging. 2) run replayed production traffic through gateway->runtime with canary routing (10%). 3) validate latency, token cost, and error surface. 4) increase to 50% then full. 5) deprecate monolith routes once all clients move.

rahul: Suggest adding a circuit-breaker on gateway if runtime latency grows, fallback to monolith variant. That keeps SLOs during runtime regressions.

leo: Observability: emit per-request trace id, batching window, batch size, runtime queue time, and per-token exec time. Add a composite metric: tokens_per_ms per model to detect regressions.

maria.c: For testing we should use the perf-replay tool and a synthetic mix that includes short prompts (<32 tokens) and long chat sessions. Need a test harness for KV cache hit/miss to verify correctness.

olivia: Security checklist: mTLS between services, KMS for model keys, RBAC for gateway admin APIs, audit logs for routing changes. For Private, expose an ops endpoint only via VPC.

jordan: One more thing — batching at runtime will change memory footprints. Need automatic admission control: refuse new requests if runtime estimated memory + queued requests > threshold. Don't OOM.

maria.c: Agreed. We'll add an admission controller that tags requests with memory estimate and uses a leaky-bucket limiter.
