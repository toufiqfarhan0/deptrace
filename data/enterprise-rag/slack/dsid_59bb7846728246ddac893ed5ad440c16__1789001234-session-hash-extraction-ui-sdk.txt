amber: SDK log hints — search for `session` or `session_hash` or the header key. Example lines we want to see (paste raw):
```
[2026-02-10T12:34:56.789Z] INFO outbound request headers: {
  "authorization": "Bearer REDACTED",
  "x-rw-session": "af3e9b2c-4f",
  "x-rw-request": "req_01H7EXAMPLE"
}
```

amber: Minimal curl we ask for (they should redact the key if needed but keep headers intact):
```
curl -v \
  -H "Authorization: Bearer <REDACTED>" \
  -H "x-rw-session: af3e9b2c-4f" \
  -H "Content-Type: application/json" \
  https://api.redwood.ai/v1/generate \
  -d '{"model":"gpt-mini","input":"hello"}'
```

marc: If they can’t share real keys, tell them to keep the Authorization header but replace the token body with `<REDACTED>` — we only need header names/values for routing. The most critical bits are the `x-rw-session` (session hash) and `x-rw-request` (request reference). If they can only provide one thing, ask for `x-rw-request` — fastest to locate in logs.

amber: For browser HAR: ask them to capture a HAR (Chrome: DevTools -> Network -> right click -> Save as HAR) and attach. In the HAR we look for the request entry and headers. For mobile: ask for a packet capture or proxy HAR from Charles/Fiddler, or the app debug log.
