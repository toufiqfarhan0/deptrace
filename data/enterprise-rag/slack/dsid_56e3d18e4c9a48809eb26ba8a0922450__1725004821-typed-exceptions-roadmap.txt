jasmin: FYI ran into SDK error chaos while wiring up the quickstart. Python raises ValueError('401'), TS gives Error with status prop, Go returns map[string]interface{} error. makes centralized retry/metrics ugly.

ori: ugh. example?

jasmin: minimal repro: auth failure -> sometimes 401 text-only, sometimes JSON `{\"error\":\"unauthorized\"}`. rate limits sometimes missing Retry-After. snippets: 

python:
```python
try:
    client.chat_send(body)
except Exception as e:
    # ValueError('401 Unauthorized')
    handle(e)
```

ts:
```ts
client.chat.send(body).catch(err => {
  // err.status === 401 or err.message === 'Request failed'
})
```

rachel: this is a big DX pain. teams can't write generic middlewares. we need typed errors + machine codes.

kevin: agree. proposal: canonical buckets (Auth, Permission, BadRequest, RateLimit, Transient, ServerError), short error.code tokens like auth.invalid_token, rate.limit_exceeded, and RFC7807-compatible payload so SDKs can map reliably. also include retry_after header + SDK-level should_retry flag and recommended_backoff_ms.

ori: +1. add a compatibility shim that inspects status and string patterns to map to new typed errors during transition.

jasmin: would love an opt-in flag first (enable_typed_errors) and a migration plan in docs + sample showing catch by class and backoff loop.

rachel: small UX detail: SDKs should expose both `status` and `code` and `meta` flat map (no deep nested objects) for telemetry tagging.

kevin: we should also consider validation errors: map 422 to BadRequest with is_validation_error=true and field hints array.
