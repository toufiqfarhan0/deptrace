Matt: quick follow-up from the console refactor RFC — wanted to check tradeoffs for splitting 'rendering' vs 'query-aggregation' paths. thinking about ownership, auth scoping, and how we keep latency SLOs stable across both.

Ilana: +1 we should avoid duplicating RBAC checks. single authorization tier that emits a capability token feels cleaner.

Song: capability token == scoped JWT? if so we need a path for short-lived tokens and a refresh handshake. otherwise we'll end up with repeated DB hits at tile time.

Matt: yes, scoped JWT (signed by control plane). idea: frontdoor verifies user + route, mints scoped token with ttl=15s for fastpath, and with longer ttl (5m) for async materialize jobs.

Priya: how does that interact with existing cache keys? we use (tenant, view, permset) currently. if token varies per request we'll lose cache hit rate.

Matt: good call — plan is token is orthogonal to cache key. cache key stays tenant:view:permset, but token is used for downstream data-service access. permset derivation stays cached.

Katie: curious about failure modes — if control plane is slow and can't mint tokens, fastpath could block. can we fallback to a signed delegation header that proxies accept?

Ilana: fallback options: 1) local cached signing key used to mint offline tokens for short window, 2) pre-warmed pool of delegation tokens per tenant for emergency reads. both have tradeoffs for revocation.

Song: revocation is painful. maybe we lean on token ttl small + audit events. long-lived tokens for background jobs only.

Priya: performance-wise, what's the overhead of adding this mint step on every request? we need latency numbers.

Matt: prototype numbers from staging: mint ~1.6ms p50, 3.8ms p95 when control plane is local. networked control plane adds ~8ms p95. overall adds ~2-9ms depending on topology.

Katie: for 99ms SLO on fast UI callbacks, adding 8ms is ok if we save 20-30ms elsewhere (cache warmups, reduced DB auth checks). but we should include a circuit-breaker: if mint fails, fastpath falls back to cached permset and short-circuit.

Ilana: agreed. propose design:

- Frontdoor: authenticate -> derive permset -> try mint scoped token (async with deadline 30ms)
- Fastpath: if token arrives, attach and call data-service. if not, use cached permset and caller-specific short-circuit header and proceed with conservative read route.
- Materialize path: gets longer TTL tokens minted once per job.
