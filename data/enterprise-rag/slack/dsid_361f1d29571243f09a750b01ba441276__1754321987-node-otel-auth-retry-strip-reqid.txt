Priya - DevEx: It's the fetch retry wrapper in sampleapp (node-fetch + retry wrapper). Root request -> 401 -> refresh token -> retry. The retry call logs show auth header replaced, but x-request-id missing.

Sasha - Infra: whoa handler finished with headers {} — that sounds like the request context (where we stash req id) is lost during retry. Are you using async-local-storage/AsyncLocalStorage for req ids?

Priya - DevEx: Yes, we have a tiny middleware that sets AsyncLocalStorage.run with {reqId} and an otel hook that pulls it into logs. But the retry code calls fetch from a different tick, might be outside the ALS context.

Matt - SDK: That matches. Also check OpenTelemetry HTTP instrumentation: if its hook (request hook/propagator) runs before our custom header injection or after the retry, it can drop the header when the request is reconstructed. Order matters.

Alex - Eng: Quick repro suggestion: run the sampleapp with NODE_OPTIONS="--require ./als-polyfill.js" and then curl to trigger 401 flow, see if req id stays. If it does, it's ALS timing.

Priya - DevEx: repro command I used: ```

Sasha - Infra: Another angle: are we redacting headers via the SDK or the logging layer? If there's a redaction rule that runs on reconstructed headers it might be wiping unknown headers. Check config for redactHeaders or a regex that matches '.*-request.*' by accident.

Matt - SDK: Good call. Our telemetry redaction defaults to ['authorization', 'cookie'] but some teams added a blanket regex in their console override. If a tenant-level redact regex like ".*token.*|.*request.*" existed, x-request-id would match.

Priya - DevEx: We checked tenant overrides and nothing matches. I also printed raw fetch options inside the retry fn and saw headers object is literally empty when it reaches the final send.

Alex - Eng: That strongly points at your retry wrapper cloning request but not cloning headers correctly. Many libs do new Request(old) which copies headers, but if you rebuild manually you can accidentally drop them.

Priya - DevEx: Here's the minimal retry snippet from sampleapp: ```js
async function retryFetch(req, attempts=1) {
  const opts = { method: req.method, body: req.body }; // oops no headers copy
  const res = await fetch(req.url, opts);
  if (res.status === 401 && attempts < 2) {
    await refreshToken();
    return retryFetch(req, attempts+1);
  }
  return res;
}
```

Sasha - Infra: Yep that's the bug. The missing headers aren't otel/ALS redaction, it's user code losing them. Still, two followups: 1) we should document that retries need to preserve context/headers, 2) SDK instrumentation could warn when requests are reissued with missing propagators (like traceparent/x-request-id).
