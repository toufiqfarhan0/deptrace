maria: quick check — monorepo edge build failing on a few customer apps when we import the node/ts SDK in SSR+edge pages. error: "ReferenceError: crypto is not defined" plus weird import resolution in Vite. Anyone seen this?

alex: yep saw that in a few repros. usually comes from mixing cjs/esm outputs and bundlers preferring one. often the bundler picks the cjs path and that pulls Node-only `crypto`.

maria: sure — here's the simplified package.json we ship:
```json
{"name":"@redwood/sdk","version":"0.12.0","type":"module","exports":{".":{"import":"./dist/esm/index.js","require":"./dist/cjs/index.js"},"./package.json":"./package.json"},"main":"./dist/cjs/index.js"}
```

sam: that looks like the common pitfall. Next/Vite SSR/edge can pick `main` or the `require` path depending on resolution conditions. the cjs build requires `crypto` which fails in the edge runtime.

alex: quick app-side workaround: force bundler to use the ESM build. For Next (webpack) you can alias to the esm entry in `next.config.js`. For Vite, use `ssr.noExternal` or `optimizeDeps` tweaks.

jin: example for Vite: add to `vite.config.ts`:
```js
export default defineConfig({
  ssr: { noExternal: ['@redwood/sdk'] }
})
```
That forces Vite to bundle the ESM source instead of resolving cjs.

maria: nice. any SDK-side fixes we should make so apps don't need per-project hacks?

sam: packaging change: remove `main` from the published package (or ensure `main` points at ESM), and make `exports` authoritative. publish with `type: "module"` and keep a separate `./cjs` folder only for consumers that explicitly `require` the package via conditional exports.

alex: alternatively, publish two separate entrypoints: `@redwood/sdk/esm` and `@redwood/sdk/cjs` and document when to use which. But conditional exports are fine if bundlers respect them.

jin: note: some older bundlers or intermediate tools ignore `exports` and fall back to `main`. so removing `main` is the better fail-safe. also ensure the ESM build uses Web Crypto APIs (globalThis.crypto) — don't fall back to `require('crypto')`.
