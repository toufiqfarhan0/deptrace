alex: We should not remove fields silently. Proposal:
1) Add new fields in v2 (session_id, kms_key_id, owner_id).
2) Mark actor_ip deprecated in v1 responses and add a deprecation notice in the schema docs and the /audit/validate API.
3) Emit both actor_email and actor_id for 90 days when available so customers can transition RBAC lookups.

jess: KMS integration notes: kms_key_id should be the key identifier only (no secrets). Only populate when the event involves key material or KMS ops. We must confirm with privacy/compliance that session_id format is OK (opaque UUID recommended). Also ensure we never log plaintext key names or KMS responses.
