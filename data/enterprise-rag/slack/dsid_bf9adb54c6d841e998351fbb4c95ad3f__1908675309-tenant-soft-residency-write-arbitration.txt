matt_h: thinking out loud — proposal for tenant-level 'soft residency' mode. goal: allow active-active writes across regions for tenants who prefer locality but can tolerate delayed data residency enforcement. sketch below, want quick reality check before an RFC.

anya.k: quick Q — is this targeting onboarding customers who can't commit to private deployments but need residency hints?

matt_h: yes. usecase: EU tenant wants EU-preferred writes, but if EU capacity is saturated we can fall back to US with additional controls so app stays online. we must preserve auditability and the ability to reconcile/migrate back.

samir: sounds useful. main tradeoffs i care about: 1) correctness guarantees for reads (stale reads?), 2) operator surface to fix residency violations, 3) security/compliance optics.

julia_p: for correctness: we should expose two read modes per-tenant: strict_read (only local region KV/caches) and eventual_read (may reflect cross-region write fallbacks). default to strict for sensitive tenants.

matt_h: agreed. operational model i had in mind: each write gets metadata header: "residency_intent": [REGION_PREF_LIST], "residency_enforced": boolean. if a write is served outside preferred region, we attach a write-escrow token and audit entry and start async replication back plus a flag for controller UI. snippet: 

```json
{"tenant_id":"t-123","residency_intent":["eu-west-1","eu-north-1"],"residency_enforced":false}
```

anya.k: how do we prevent accidental PII leakage during the window when data is outside preferred region? do we require additional encryption or ephemeral keys?

samir: we can require that for tenants with residency policy set to "soft+encrypted" the runtime uses a tenant-specific envelope key that is only resolvable in preferred regions. if we fallback, we store ciphertext but keys stay in KMS in preferred region so data is unreadable until we rehydrate. this adds latency to reads though.

julia_p: that seems reasonable for high-sensitivity tenants. operationally we need a clear on-call play: list of outstanding escapes, an auto-remediation job that tries to reconcile every 5m, and an alert when >N outstanding for >T minutes.
