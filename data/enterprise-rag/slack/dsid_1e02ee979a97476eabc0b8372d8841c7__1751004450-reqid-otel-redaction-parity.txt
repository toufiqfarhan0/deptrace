oli: implementation idea: SDK exposes `telemetry.pre_export_hook(span_or_batch)` which is invoked just before OTLP payload serialization. default applies our redaction rules (regex + key blocklist). example config: 
```yaml
telemetry:
  redaction_rules:
    - type: regex
      pattern: "(?i)[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}"
      replace_with: "[REDACTED_EMAIL]"
    - type: key_blocklist
      keys: ["password","ssn","credit_card"]
```

karen: and SDKs should also provide a `telemetry.pre_process_span` callback where integrators can mutate span attributes (e.g., additional redaction, normalization) before the exporter sends them. tests should fail if any PII shows up in exported OTLP payloads.

dana: small middleware snippets to standardize propagation: python/fastapi: 
```py
async def reqid_mw(req, call_next):
  rid = req.headers.get('x-request-id') or str(uuid.uuid4())
  baggage.set_baggage('request_id', rid)
  structlog.threadlocal.bind_threadlocal(request_id=rid)
  resp = await call_next(req)
  resp.headers['x-request-id'] = rid
  return resp
```
node/express: 
```js
app.use((req, res, next) => {
  const rid = req.headers['x-request-id'] || uuid.v4();
  req.request_id = rid;
  // attach to current span when tracer has one
  const span = tracer.getCurrentSpan && tracer.getCurrentSpan();
  if (span) span.setAttribute('request_id', rid);
  res.setHeader('x-request-id', rid);
  next();
});
```

oli: note: logging levels — don't send DEBUG-level request bodies to exporters by default. OTLP exporter config should have a `min_export_level` (default INFO) and we should gate body capture behind an explicit `capture_bodies: true` flag. avoids accidental leaks in dev.
