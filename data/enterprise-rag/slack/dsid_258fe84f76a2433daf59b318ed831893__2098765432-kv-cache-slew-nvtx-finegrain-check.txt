maria: i want to keep per-request NVTX spans (for correlation), but we should stop creating a unique string per prefetch call. suggestion: NVTX range naming rules: prefix with domain (REQ/RT/KV), then static op name, then short numeric tags only when necessary. examples: `REQ:START`, `KV:PREFETCH`, `KV:COMMIT:shard=3` (shard numeric). avoid long UUIDs in names.
julie: +1. also propose we put per-request id into the trace as an annotation/metadata instead of the range name. perf tools can filter by annotation key `req_id`.
sam: quick patch i tested replaces snprintf-heavy names with fixed const char* and nvtxRangePushEx with a small `nvtxEventAttributes_t` containing the `message` pointer and an `uint64` for req_id in `payload.ll`. results: wallclock in the trace improved by ~6%-8% and kernel launches now overlap more. posting the diff snippet: 
```cpp
static const char* KV_PREFETCH = "KV:PREFETCH";
nvtxEventAttributes_t attr = {0};
attr.version = NVTX_VERSION;
attr.size = NVTX_EVENT_ATTRIB_STRUCT_SIZE;
attr.messageType = NVTX_MESSAGE_TYPE_ASCII;
attr.message.ascii = KV_PREFETCH;
attr.payloadType = NVTX_PAYLOAD_TYPE_UNSIGNED_LONG_LONG;
attr.payload.ull = req_id;
nvtxRangePushEx(&attr);
```
