Iris Novak: Quick heads-up — strange behavior in the SDK fn-call helper when arguments use a union type (array | null) combined with enum item values. In json_mode the enum field gets coerced to its first enum option on retry instead of staying null. Broken in sampleapp smoke tests.

Iris Novak: Minimal repro (JS):
```js
await redwood.sdk.callFunction({
  name: 'inventory.patch',
  arguments: { tags: null, mode: null }, // mode is enum: [null, 'soft', 'hard']
  jsonMode: true
})
// simulate auth refresh / retry
```
After retry we see { tags: [], mode: 'soft' } sent to the backend.

Tom Becker: whoa, mode -> 'soft'? That's wild. Is there a defaulting pass in the serializer that picks the first enum value?

Iris Novak: Looks like it. I traced it to _coerce_union() in the serializer: when encountering a union with array|null|enum it tries to pick a candidate by running validators in order. On retry, the object shape is reconstructed and the enum validator runs before the null check, so it picks 'soft' as the first matching enum candidate.
