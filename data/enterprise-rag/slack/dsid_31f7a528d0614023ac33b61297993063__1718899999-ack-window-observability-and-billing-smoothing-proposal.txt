devon: proposal: add an "ack-window" tag to span traces + emission to the usage event stream. when two sessions share same client session id and overlap within ack-window (default 30s), mark the second set of tokens as provisional and correlate to the first before confirming. that lets console show a single blended line and lets billing backfill or reverse provisional credits if dedupe happens.

maria: UX asks: console should show both provisional and confirmed numbers with a tooltip: "provisional can be adjusted on reconciliation". Also need an alert rule for large provisional spikes.

if request.headers['X-Client-Session'] == previous.session && now - previous.last_event < ACK_WINDOW:
