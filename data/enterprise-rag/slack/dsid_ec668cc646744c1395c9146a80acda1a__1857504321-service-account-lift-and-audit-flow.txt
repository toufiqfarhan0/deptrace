Alisa: FYI partner infra wants a way to temporarily bump per-API-key limits for our internal service accounts (partner ingestion pipelines). Asking for a simple, auditable flow + console UI.
Mike: Agree we need temp lifts, but we should avoid special-casing. Proposal: per-key token-bucket + optional temporary override record that decays (burst credits).
Priya: Strong +1 for audit + expiration. Also need guardrails so a compromised key can't get unlimited credit. Require owner approval and 2FA for manual grants.
David: UX note: Console should show active overrides, who granted them, TTL, and a one-click revoke. Also a history link to the audit log.
Mike: Implementation sketch: store override as metadata tied to key id. Runtime checks: if override exists, evaluate min(override.qps, global-cap) and consume from a separate burst_credit meter. On expire, fall back to baseline policy.
Mike: Example override shape (proto):
```
override: {
  key: "svc-ingest-42",
  grant_type: "temporary",
  qps_limit: 200,
  burst_tokens: 1000,
  expires_at: "2025-05-03T18:30:00Z",
  reason: "backfill / partner onboarding",
  granted_by: "alisa"
}
```
Priya: Also require a whitelist for which keys can receive overrides (internal service accounts + partner integrations). No user-owned keys.
Alisa: Good call. We should default overrides to "non-production" unless an approver flips it on.
David: Telemetry: emit metrics per_key.override_active, per_key.burst_remaining, per_key.override_owner, and logs to audit stream with HMAC'd metadata. Make the override id available for tracing.
Mike: For enforcement we can check override in the routing layer before token bucket. Pseudocode:
```
if (override.exists && now < override.expires_at) {
  limit = min(override.qps_limit, org_max_qps);
  allowed = token_bucket.allow_with_burst(limit, override.burst_tokens);
} else {
  allowed = token_bucket.allow(org_limit);
}
```
Priya: Abuse scenarios: stolen key used to exhaust override. Mitigation: auto-revoke if unusual pattern (cross-region, new IP), send interrupt to owners, require re-approval if revoked.
Alisa: Policy question: do we let partners request overrides through support, or do they file infra tickets? I want minimal manual ops. Maybe a console request flow that creates a vetting ticket.
David: +1 for request -> approval -> auto-grant. The approval step should be configurable by team (some teams can auto-approve internal SAs).
