Maya Chen: Uploaded the updated vectors preview mock for the batch + rerank export flow — sketch link: https://sketch.redwood/designs/vec-preview-v6. Can folks skim toolbar states and the multi-select behavior? Main ask: keyboard nav, screen-reader copy, and the exact export CTA text.

Sam O'Neill: Quick pass: the toolbar feels cramped when 8+ items are selected. The overflow menu hides the delete action. Might need a condensed state or a horizontal wrap. Also 'Export selected' is ambiguous in a multi-export product. :thinking_face:

Priya Patel: +1 on the label. For clarity I prefer an explicit count in the CTA when possible: e.g., `Export 3 vectors`. For small screens we can compress to `Export (3)` and show full string on hover.

Alex Rivera: For screen readers we should announce the selection changes and the available action. Suggest adding an `aria-live="polite"` region that says: "3 vectors selected" on change. Also ensure the export CTA has `aria-disabled` when zero selected.

Jordan Li: One accessibility nit: the vector rows use `role="rowgroup"` + `role="row"` today which breaks VoiceOver nested semantics. We should keep it simple: `role="list"` + `role="listitem"` for the preview list and manage selection with `aria-selected`. Also use roving tabindex instead of managing multiple tabbable items. Example:

```
// roving tabindex pattern (simplified)
<li role="listitem" tabindex="0" aria-selected="true">Row A</li>
<li role="listitem" tabindex="-1" aria-selected="false">Row B</li>
```

Rafael Gomez: Design copy suggestion hierarchy: primary CTA -> `Export 3 vectors`; secondary -> `Export (selected)`? That feels odd. Alternative: primary `Export` and a small counter `3 selected` next to it. The counter should be visible and programmatically exposed: `span aria-hidden="true">3 selected</span>` + `span class="sr-only">3 vectors selected</span>` for SR.

Sam O'Neill: Performance/UI note: when selecting a lot of vectors, the toolbar should switch to a 'compact mode' (smaller microcopy, tighter padding) rather than moving actions into overflow — prevents accidental tap misfires on mobile.

Priya Patel: Keyboard flow: Tab to the list, then use arrow keys to move focus between rows (roving). Space toggles selection. After selection, focus should remain on the row, not jump to the toolbar. The toolbar gets updated live but isn't auto-focused. Users who want to perform action can press `Shift+Tab` once.

a11y-bot: Checklist: 1) Focus order preserved (list -> toolbar). 2) `aria-live` for selection count. 3) actionable items have accessible names (e.g., `Export 3 vectors`). 4) Contrast for counter chip >= 4.5:1. 5) Keyboard: Arrow nav, Space to select, Esc to clear selection.

Alex Rivera: Minor copy tweak for export modal: header now reads `Export vectors` — suggest `Export vectors (selected)` when launched from toolbar with selection, and `Export vectors` when launched from empty state. Keeps context clear.

Rafael Gomez: UX microcopy for empty-state export disabled: `Select vectors to enable export` (short and actionable). For tooltip we can add `Tip: press Space to select` on first use.

Jordan Li: A11y detail: when the selection count updates, VoiceOver sometimes reads both old and new counts if we don't clear the live region first. Use `aria-relevant="additions text"` and clear the node before writing the new text.

Sam O'Neill: Visual: need a visible focus ring on the row when keyboard-focused. Current designs hide it for hover only. Use 2px solid outline with variable token color.
