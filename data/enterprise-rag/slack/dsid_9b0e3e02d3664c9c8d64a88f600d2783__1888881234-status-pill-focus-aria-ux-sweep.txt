mona: Quick accessibility sweep notes for the dashboard "status" pill interactions. Couple of issues spotted during keyboard walkthrough.
diego: What did you find?
mona: Repro: tab into a model row -> focus the status pill -> press Space to open status menu. NVDA doesn't announce that the pill is a menu button, it reads only the visible label.
kate: That sounds like missing role/aria-haspopup/aria-expanded states. The pill looks like a semantic button but might be a plain div.
owen: Also noticed focus order oddness when you open the menu: focus jumps to the last menu item instead of the first, which is confusing for keyboard-only users.
mona: Visual: focus outline on the pill is also very subtle in high-contrast mode. Auto-scan flagged a 1.6:1 ratio for the focus halo vs bg on the dark-high-contrast theme. Screenshot: https://attachments/reports/status-pill-focus-188.png
diego: Proposed fixes: (1) change pill container to a real button or role="button" with tabindex=0, (2) add aria-haspopup="menu" and aria-expanded toggled on open/close, (3) ensure menu uses roving tabindex with initial focus on first item.
kate: Also add aria-label combining the status name + action e.g., aria-label=\"Status: Running. Open status options\" so screen readers know action and state.
mona: Example pattern: 
```
<button class="status-pill" aria-haspopup="true" aria-expanded="false" aria-label="Status: Running. Open status options">
  Running
</button>
// on open: set aria-expanded="true" and focus first menu item
```
owen: For focus ring: use a thicker outline and a color that meets 3:1 contrast. Suggest CSS var --focus-strong (#ffd66b on dark-high-contrast yields ~3.2:1). Also add outline-offset: 2px for visibility.
diego: We'll add keyboard e2e that tabs to pill, hits Space, expects focus on first menu item and aria-expanded="true". Also test the pill reads aria-label correctly with VoiceOver on mac in CI smoke.
kate: Edge case: when status text updates (e.g., Running -> Failed) we should update accessible name and announce change via a polite live region only if the change is not due to hover (to avoid spam).
a11y_bot: Scan summary: status-pill element lacks role/button semantics in some instances; aria-expanded not present; focus jump on menu open; focus ring contrast fails in dark-high-contrast theme (1.6:1). Recommend above fixes and add a regression e2e for keyboard + screen reader smoke.
