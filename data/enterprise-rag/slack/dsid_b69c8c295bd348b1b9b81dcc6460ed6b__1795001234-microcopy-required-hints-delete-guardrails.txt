anya: Quick sync on small-forms pattern. I'm debating between tiny hint text "Required" under labels vs inline suffix "(required)". Goal: keep compact but accessible. Thoughts? :sparkles:

ben: I prefer the suffix `(required)` for screen readers if we put it in the visible label text, e.g., `API key name (required)`. Keeps label semantics intact.

lina: Agree. Visual asterisk alone is fragile. If we must use an asterisk, pair it with `aria-label` or visually-hidden text.

sam: Practicality note: a full `Required` word increases label length in dense tables. Could we show `Required` on focus or when it's empty? That avoids clutter but still surfaces to keyboard users.

anya: Good point. Concern: showing/hiding `Required` might confuse SR users unless we manage DOM presence consistently. If hidden visually, keep it in the label for SRs.

ben: Implementation idea: always include `required` in the accessible label, but toggle a low-contrast visual badge for sighted users. So SRs hear it always, visual users only when helpful.

lina: For error patterns: inline errors <em>and</em> an optional top summary on submit. Summary should be keyboard-focusable and announce via `role="alert"`. Also include `aria-live` polite for incremental inline errors.

sam: UX nit: when there are many inline errors, users get lost. The summary must link to fields (anchor links) and we should trap focus to the summary region after submit so keyboard users can jump.

anya: Example summary copy: `We found 2 problems. Fix them or press Esc to return.` Might be too wordy. Suggestions?

ben: Shorter: `2 errors — jump to first` with a link. Also track `validation.summary_shown` and `validation.summary_link_click` events.

lina: Destructive flow: small deletes (single API key) -> confirm modal + undo toast (40s). Bulk deletes -> multi-select modal with a summary row and typed confirm only if >50 keys or org-level. Typed confirms are heavy; reserve them.

sam: For typed confirm copy, prefer `Type the org name to confirm:` instead of `Type DELETE` 3; makes it contextual and prevents accidental muscle-memory.

anya: Accessibility checklist for the modal: ensure focus is moved into the modal, restore focus to trigger, make the confirm button disabled until checkbox/typed input done, and provide `aria-describedby` linking to the warning text.
