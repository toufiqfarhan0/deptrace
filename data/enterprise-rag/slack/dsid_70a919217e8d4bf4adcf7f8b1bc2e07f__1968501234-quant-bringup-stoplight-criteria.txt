alex_liu: Quick sync — proposing a 'stoplight' gating system for new-model bring-up and quant experiments before any canary. TL;DR: green = pass all core evals + <=1% relative regression on QA/semantic + latency <=1.2x baseline; yellow = minor regressions requiring manual triage; red = fail (block canary).

maria_singh: Can you list the concrete evals and pass thresholds? Which prompt sets count as 'core'?

alex_liu: Core prompt sets: core_prompts_v2 (1000 samples), dialogs_smoke_100, safety_suite_v3 (250), hallucination_spotcheck_200. Pass criteria:
- QA F1 (core_prompts_v2): >= baseline - 0.01 absolute or <=1% relative regression (whichever is stricter)
- Semantic accuracy (dialogs_smoke_100): >= baseline - 0.02
- Safety (safety_suite_v3): no new high-severity failures; medium failures <= baseline + 0.5%.
- Hallucination spotcheck: model must not introduce novel named-entity hallucinations > 2%.
- Latency: P95 <= baseline * 1.2 and median <= baseline * 1.15
- Embeddings cosine (if applicable): avg cosine >= baseline - 0.005

sam_wright: What about quantized variants? We need explicit sample-level parity for quant runs.

alex_liu: For quant runs (int8, q4), require sample-level top-1 match >= 97% on core_prompts_v2 and no safety regressions. If a quant variant fails but fp16 passes, mark as 'yellow' and require follow-up (pruning kernels, retune kv-cache). If both fail => red.
