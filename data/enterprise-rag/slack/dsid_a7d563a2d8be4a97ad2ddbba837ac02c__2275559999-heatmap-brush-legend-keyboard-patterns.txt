Maria Chen: Quick design callout — proposal to change heatmap legend to a compact range-brush control instead of the static gradient. Allows users to brush a value range to filter the dashboard and exposes keyboard controls for accessibility. Thoughts?

Jon Park: Love the brushing idea for exploration. Concern: perf when multiple dashboards sync filters — will brushing trigger heavy re-renders?

Maria Chen: Good point. Plan is to debounce brush events (200ms) + send aggregate range payloads to the store, not per-pixel updates. Also add a lightweight summary count in the legend while dragging to avoid a full chart rerender.

Lee Rodriguez: For keyboard, we need clear ARIA semantics. Suggest role=slider with aria-valuemin/aria-valuemax/aria-valuenow and arrow keys to nudge bounds. Example:

```
<div class="heatmap-legend-range" role="group" aria-label="Value range filter">
  <div role="slider" aria-valuemin="0" aria-valuemax="100" aria-valuenow="20" tabindex="0">min</div>
  <div role="slider" aria-valuemin="0" aria-valuemax="100" aria-valuenow="80" tabindex="0">max</div>
</div>
```

Samir Patel: Microcopy: when users focus the legend sliders, readout should be concise: e.g., "Filter values 20 to 80 (press arrow keys to adjust)". Also add an explicit "Reset range" button.

Tia Nguyen: Color accessibility: gradient alone isn't great for colorblind folks. Suggest adding optional pattern overlays (dots/lines) for binned ranges, and a high-contrast outline when a range is selected. We should test with Deuteranopia simulator.

Maria Chen: Agree. Option: by default use a colorblind-friendly sequential palette, and expose a toggle "patterns for accessibility" in the legend menu. Patterns should be subtle so they don't obscure heat intensity.

Jon Park: UX question: do we show smoothed vs raw heatmaps when brushing? Smoothing helps readability but hides spikes/outliers. Maybe an explicit "Smoothing: on/off" toggle in the legend so users know what's happening.

Lee Rodriguez: If we add smoothing toggle, include an inline help icon that explains: "Smoothing applies a gaussian kernel to highlight dense regions and reduce noise; disabled = raw counts". Keep it short.

Samir Patel: For outliers — prefer capping with an overflow bin shown as ">= X" in the legend rather than compressing color range. That keeps the scale interpretable. Also show a tiny badge with count of cells in overflow.

Maria Chen: Decision proposal (so we can move to mocks): 1) Compact range-brush legend with dual sliders + keyboard support + ARIA roles. 2) Debounced brush events + lightweight count summary while dragging. 3) Colorblind-friendly palette by default + optional pattern overlay. 4) Smoothing toggle visible in legend with short help copy. 5) Outlier overflow bin at top of legend with count badge. 6) Reset range control and clear label readouts for screen readers. Anyone object?
