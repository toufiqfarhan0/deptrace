Alice Zhang: Quick notes from today's two-stage sampling run on the new draft-13B bring-up. TL;DR: ~1.9x tokens/sec vs our previous speculative decode baseline, but a small quality dip on the summarization eval set. Posting config + logs for context.

Ben Ortiz: Nice. Which eval suite did you run? ROUGE or humans? :eyes:

Alice Zhang: Both. Automated: ROUGE-L on our internal summarization set (500 prompts). Human: pairwise preference (n=200). ROUGE-L down ~0.9 pts; human pref baseline 52% -> 48% (p~0.12). Not catastrophic but worth investigating.

Carol Ng: Can you sketch the pipeline? By two-stage sampling you mean small draft sampler -> large model rescoring/expansion, right?

Alice Zhang: Exactly. Stage1: 3B draft model samples k candidates (k=4) with temp=0.9. Stage2: 13B scores candidates and then does the final greedy decode for the picked candidate. We reuse the draft prefix via KV cache transfer to avoid recomputing tokens where possible. Config and run command below.

Alice Zhang: ```
# pipeline config (abbrev)
stage1: model: draft-3b quant: fp16 samples_k: 4 temperature: 0.9
stage2: model: main-13b quant: fp16 scorer_only: true fallback: autoregressive
eval: suite: summarization_v2 n_prompts: 500 metrics: [rouge_l, length_ratio]
```

Alice Zhang: run: `./harness/run_eval.sh --config configs/two_stage_samp.yaml --out /tmp/run178250`

Eva Patel: How does this compare to our existing speculative decode kernel? Any tradeoffs on KV cache churn / batching? :thinking:

Alice Zhang: Compared to speculative decode, two-stage is simpler to parallelize: stage1 samples for entire batch then stage2 rescoring fits batching nicely -> less KV thrash in practice, which explains the ~1.9x tokens/sec. Speculative decode had finer-grained interleaving which gave slightly better alignment with the large model's generation distribution, which may explain the small quality gap.
