Mike: heads up — onboarding a new HF chat model (meta-llama-chat-3). Using a Jinja chat_template with an optional `assistant_note` block. When the block is empty the rendered prompt drops the assistant role header and Redwood treats the assistant text as system. This produced a measurable eval regression on convo-turn coherence.
Anya: can you paste the template + rendered output so we can see the exact whitespace/markers?
Mike: sure — simplified template:```jinja
{% if system %}- role: system\n  content: {{ system }}\n{% endif %}
{% if assistant_note %}- role: assistant\n  content: {{ assistant_note }}\n{% endif %}
- role: user\n  content: {{ user }}
```Rendered when assistant_note is empty becomes:
```text
- role: system\n  content: You are a helpful assistant.\n- role: user\n  content: What is the weather?\n```Note the missing assistant block/marker — the user message looks fine but downstream role-splitting puts the following assistant content in the wrong bucket.
Kevin: this is subtle — two possible causes: Jinja whitespace trimming collapsing the empty `role:` line, AND our HF->Redwood converter expects an explicit role header line (we split on `- role:`). If that header disappears, we merge content. Also tokenizer boundary matters: if there's a leftover leading space before `assistant` it can be tokenized as different tokens and downstream parsers fail.
Lina: I think there was a change in the converter where we `.strip()` empty blocks and removed the role header entirely (PR 0.7.3). Repro in code:```py
# convert_chat_template
for msg in rendered_msgs:
    if msg.strip():
        out.append(f"- role: {role}\n  content: {msg}")
```If `msg` is empty we skip the whole `- role:` line. That matches what Mike saw.
Mike: also saw config.json differences between HF model artifacts: some have `add_bos_token: true` and custom `bos_token` that causes the tokenizer to insert a token before the first role line, shifting indices in our splitter. Example: "add_bos_token": false fixes one variant.
deploy-bot: eval-runner: 2 failing evals (chat-turn-coherence, turn-helpfulness). See run/2026-03-19-ml-eval/4827 for diffs.
Anya: quick mitigation options: (1) change Jinja template to always emit an explicit assistant header even when empty (add sentinel empty string), (2) change converter to keep role header even if content is empty, (3) normalize tokenizer configs (`add_bos_token=false`) during conversion.
Kevin: I pushed a small hotfix (pr/624) that keeps the role header line and inserts an explicit empty content string (`content: ""`) when a block is falsy. Also added a defensive normalize step for `config.json` that forces `add_bos_token=false` and maps `bos_token` -> `<s>` if missing.
