miguel: sketch of entitlements endpoint we're proposing:

```
POST /v1/entitlements/eval
{
  "tenant_id": "org_123",
  "route": "inference/chat",
  "principal": "svc-abc",
  "sample_prefix_len": 32
}

200 OK
{
  "mode": "hard",            // hard | annotate | advise
  "decision": "allow",      // allow | deny | advise
  "matched": ["route.chat.*"],
  "ttl": 45
}
```

miguel: question: should `decision` ever be `advise` separate from `mode`? thinking `mode` is enforcement policy, `decision` is evaluation result.

rohit: yep. `mode` controls router behavior. `decision` is the entitlement check result. router returns `deny` when mode=hard && decision=deny. router can treat mode=advise as hint only.

anya: rollout controls: per-tenant deterministic rollout via config `rbac.enforce_pct`. router calculates `hash(tenant_id) % 100 < pct`. this helps gradual ramp.
