Priya K.: Sounds like proxy is splitting chunks or closing the socket early. Common culprits: proxy idle timeout, buffer limits, or NGINX/HAProxy stripping chunk boundaries. Ask customer to check proxy logs for 502/504 or \"upstream prematurely closed connection\". For nginx: ensure `proxy_buffering off; proxy_http_version 1.1; chunked_transfer_encoding on;` and increase `proxy_read_timeout`.

Luke H.: Can repro locally with Node streaming to simulate parsing error. Example that fails when a chunk boundary lands mid-json:
```js
const fetch = require('node-fetch');
(async()=>{
  const res = await fetch('https://api.redwood.ai/v1/streams?mode=json',{
    headers: { Authorization: 'Bearer sk-xxx', Accept: 'text/event-stream' }
  });
  const reader = res.body.getReader();
  let buf = '';
  while(true){
    const {done,value} = await reader.read();
    if(done) break;
    buf += Buffer.from(value).toString();
    try{
      // naive: try parse whole buffer each chunk -> will fail if truncated mid-object
      JSON.parse(buf.replace(/^data: /gm,''));
    }catch(e){
      console.log('partial parse, waiting for more...');
    }
  }
})();
```

Maria S.: Ran that and got: `SyntaxError: Unexpected end of JSON input` at attempt to parse on chunk 7. Their proxy's logs show socket reset at the same time.

Sam Ops-bot: Backend logs for r-7f3b show: `writev failed (32: Broken pipe)` then `upstream response prematurely closed`. Upstream returned 200 and started streaming, then connection reset by peer after ~48s. No error on our application layer.

Priya K.: Mitigations we can recommend to the customer:
- Short term: request full JSON (non-streaming) by using `Accept: application/json` or `?stream=false` so they avoid chunked transfers.
- Client change: use an event-stream/SSE parser that processes per-event JSON (`EventSource` or server-sent event parsers) and buffers per `\\n\\n` delimiter rather than trying to JSON.parse the entire incremental buffer.
- Proxy: increase keepalive/idle timeout (ALB/nginx default 60s can bite), turn off proxy buffering, ensure HTTP/1.1 keepalive to upstream.
- Server: we can consider returning each top-level object as a complete SSE `data:` event (ensure each event is a self-contained JSON object) to be more streaming-safe for brittle proxies.

Luke H.: Also note: if a proxy is reassembling and drops TCP segments or enforces a max header/body chunk, it can cut a chunk mid-json. Customer's description matches corporate IDS/firewall meddling.
