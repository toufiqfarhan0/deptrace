Leah: quick RFC follow-up: instead of a full rewrite on the hot path, what if the gateway supports schema-negotiation and a "shadow" compat path for verification?
Matt: explain shadow path?
Leah: gateway forwards canonical request to runtime as usual, and in parallel sends original payload to compat-service which performs a rewrite and validity checks, logs diffs. no added latency to runtime path.
Priya: shadowing avoids p99 regressions, good. how do we convince customers the rewrite is safe before flipping it on?
Dmitri: add a dry-run mode where compat-service posts a diff URL and a confidence score. we surface diffs in Console per-tenant.
Leah: plus a policy layer: rules can be mode=shadow|rewrite|sample|log-only. defaults to shadow during canary.
Matt: storage for rules? file + push or central service? prefer central store so we can patch quickly.
Priya: central rulestore + per-gateway cache with watch. rule schema should include route selectors, match predicates (headers/json-path), and modes + rollout percentages.
Dmitri: security: shadow path must inherit caller auth and scrub secrets in diffs. never persist full payloads for external customers, only hashes and selected fields.
Sam: product asks for a tenant visible "compat confidence" indicator and a way to request a rewrite trial. also need retention policy for diffs.
Leah: suggested rollout: internal shadow -> 0.1% external shadow -> gather diffs for 48h -> 1% rewrite sample -> full rewrite opt-in. Ask: how to detect silent breakages (semantics change)?
Priya: run side-by-side evals on a small prompt set; compute metric drift (tokens per response, length, top-k overlap). flag on divergence threshold.
Matt: telemetry: rule_hits, shadow_diffs_count, rewrite_accept_rate, semantic_drift_score, per-tenant. surface alerts when drift>threshold or rewrite_error_rate>0.5%.
Dmitri: implementation pieces: 1) rulestore RFC + schema, 2) gateway shadow sender (async), 3) compat-service dry-run API and diff endpoint, 4) Console diffs + confidence UI, 5) sampling and ops playbook.
Leah: ops playbook (short):

- If shadow errors > 1%: move to log-only and investigate.
- If semantic drift exceeds threshold: block rewrite and run extended audits.
