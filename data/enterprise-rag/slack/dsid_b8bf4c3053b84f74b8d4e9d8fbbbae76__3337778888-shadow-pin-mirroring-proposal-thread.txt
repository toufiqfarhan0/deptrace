carla: Quick idea - propose a 'shadow pin' pattern for model releases. Keep a candidate model pinned as a shadow target that receives mirrored requests for validation (no user-visible routing changes). PoC proposal below.

ben: Interesting. How does this differ from canary?

carla: Canary routes a small % of live traffic, which can impact SLAs. Shadow is read-only mirroring: requests are copied to shadow replica asynchronously so prod latency isn't affected. Good for correctness/regression checks.

dinesh: Cost/CPU note: naive mirroring doubles inference. We should support sample_rate and lightweight payloads (no KV cache warmups for every mirror) or use sampled mirrors.

alice: Sketch of the minimal rollout metadata we need - thinking fields, semantics and defaults:
{
  "pin_type": "shadow",           // shadow | canary | hard
  "shadow_ttl": "72h",           // ephemeral default
  "mirror_rate": "0.05",         // sample fraction (0.0-1.0)
  "scrub_inputs": "true",        // run input-scrub step before mirroring
  "quality_checks": ["exact_match_rate", "logprob_delta"],
  "cohort": "release-2026-03-xx",
  "telemetry_tag": "shadow-compare-v2"
}

emily: A few compatibility caveats: tokenization parity, model family id, and deterministic sampling key must be part of the contract. Promotion should be blocked if shadow metrics regress beyond thresholds.

carla: Agreed. Promotion policy should be explicit: shadow -> canary -> promote. Shadow alone never flips prod routing. Also, shadow pins must be auto-evicted by reconciliation job when TTL expires.

dev-bot: :rocket: deploy hook: mirror-service v0.3 applied to cluster-2 (for testing)

dinesh: Also: privacy. Mirroring must respect scrub_inputs or be disabled for tenants with PII constraints. Add field "masking_policy": "scrub|hash|drop" in schema and ensure ops can opt-out.

ben: Observability requirements: per-pin diffs, histograms of token-level divergence, alerting on high drift, and a summary that can be surfaced in Console per-route. We should persist shadow compare traces for at least 7 days.

alice: Implementation notes: lightweight mode can only mirror metadata + embeddings for expensive models and run full-token inference on sampled requests. We'll need a config knob at pin-level: "mirror_mode": "full|meta|sampled_full".

emily: Edge cases: what if the shadow uses a different vocabulary / tokenizer? Reject shadow pin at registration with a compatibility check (fail-fast) or allow but mark as 'incompatible-tokenizer' in metadata.

carla: Ops safety: default mirror_rate 0.01 for first 24h, then allow operators to increase. Shadow pins should not consume Dedicated reserved capacity unless explicitly allowed.
