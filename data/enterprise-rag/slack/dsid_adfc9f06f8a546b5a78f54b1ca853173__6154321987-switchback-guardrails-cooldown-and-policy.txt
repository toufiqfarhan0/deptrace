tara: Follow-up from today's multi-region sync: ops asked for a compact machine-check for when an active->standby can be switched back. they want clear guardrails + a cooldown and to ensure residency rules are never violated.

oz: Idea: expose two independent boolean gates per-tenant: safety_ok and policy_ok. auto-switchback allowed only if both true and stable for a window. Keep policy_ok simple (control plane boolean) and safety_ok composed of runtime signals.

ben: Runtime signals we can emit today: last_applied_seq{tenant,region}, inflight_leases{tenant,region}, ingress_queue_len{tenant,region}, region_time_skew_ms{pair}. Proposal thresholds: seq_delta <= 1 for 60s, inflight_leases==0, ingress_queue_len==0, skew < 500ms. All must hold to set safety_ok=1.

maya: Policy side: control plane flags: tenant.residency_mode in {hard,preferred,none} and tenant.allow_cross_region_writes boolean. If residency_mode==hard and target-region != resident-region -> policy_ok=false always. For preferred we allow auto but surface warning.

tara: Ops wants a single composite metric for alerting. oz: We'll emit switchback_gate{tenant,region}=0/1 and label reason={caught_up,policy_block,inflight,skew,operator_lock}. Also counters: switchback_attempts_total and switchback_fail_reasons_total.

ben: Add a cooldown: after any successful switchback set tenant.switchback_cooldown_until = now + 30m (configurable per-org). During cooldown auto-switchback is disabled to prevent oscillation.

maya: For tenants with external nondeterministic side-effects (webhooks, 3rd-party callbacks) add tenant.requires_deterministic_replay flag which defaults to true; when true auto-switchback is disabled and manual replay verification is required.
