alex: My current plan is to add an aws_kms_key_grant for the service account ARN generated via the OIDC role, rather than changing the key policy. Any gotchas I'm missing? Also worried about helm creating the SA after TF runs and the grant failing because ARN doesn't exist yet.

jamie: generally we prefer key grants + a constrained key policy entry for cross-account cases, but for IRSA it's fine to make a grant to the role principal that the OIDC provider will assume. main gotcha: make sure the Principal matches the assumed role ARN and include the sts:AssumeRole condition if you have session tagging requirements.

jamie: also :point_up: the helm timing you mentioned is real — helm can create the ServiceAccount after TF runs. i usually either apply the SA first (kubectl/apply) or add an explicit dependency in TF (kubernetes_manifest or helm_release -> depends_on sa resource) so the ARN is stable before you create the grant.

sasha: sample tf snippet that worked for us recently:

```
resource "aws_iam_role" "vectorizer_irsa" {
  name = "vectorizer-irsa-${var.env}"
  assume_role_policy = data.aws_iam_policy_document.irsa_assume_role.json
}

resource "aws_kms_key" "customer_data" { ... }

resource "aws_kms_grant" "vectorizer_decrypt" {
  name            = "vectorizer-decrypt-${var.env}"
  key_id          = aws_kms_key.customer_data.key_id
  grantee_principal = aws_iam_role.vectorizer_irsa.arn
  operations      = ["Decrypt", "GenerateDataKey"]
  retiring_principal = "arn:aws:iam::${data.aws_caller_identity.current.account_id}:root"
}
```

sasha: if you can't reference the role ARN directly because the SA is coming from helm, create the IRSA role in TF (so it exists) and then helm can annotate the SA to map to that role. or create a lightweight k8s manifest for the SA in Terraform so ordering is explicit.

lee: another option is to rely on key policy entries instead of grants. key policy can allow principals from the account/role pattern and is slightly more tolerant to ordering because it's not a separate resource, but it's less flexible for scoped grants and auditability.
