anika: Anyone else seeing mypy fail on async streaming endpoints from the autogen SDK when we publish pypi packages? pyright is fine but mypy screams.

anika: Minimal symptom: client.stream_events -> AsyncIterator becomes untyped in the distributed package (shows as AsyncIterator[object] or Any). Locally in source it looks correct.

river: I ran into this once. IIRC the wheel build step strips typing info because of our pyi generation pipeline. We publish both .py and .pyi but the pyi for streams was missing the union.

maya: can you paste the actual error?

anika: mypy output: "error: Item of \"AsyncIterator[object]\" has incompatible type \"object\"; expected \"Union[EventChunk, StreamError]\"". Happens when you do `async for chunk in client.stream_events(...)` and access chunk.payload.

river: repro snippet I used: 
```py
from redwood import AsyncEventsClient

async def drain():
    async for c in AsyncEventsClient().stream_events("abc"):
        # mypy: Item is object
        if isinstance(c, EventChunk):
            print(c.payload)
```

river: pyright is fine because it can narrow with isinstance checks even when pyi is loose, but mypy needs the declared union.

maya: what pydantic/version and python are you on? we saw pydantic v2.4 recently make subtle changes in how BaseModel subclasses are represented in pyi.

river: python 3.11, pydantic 2.4.1. The generated models are fine, it's the client .pyi that loses the union and reverts to object.

tom: quick workaround for consumers: add a typed alias locally or cast the iterator like `client_it = cast(AsyncIterator[Union[EventChunk, StreamError]], client.stream_events(...))`. ugly but works.
