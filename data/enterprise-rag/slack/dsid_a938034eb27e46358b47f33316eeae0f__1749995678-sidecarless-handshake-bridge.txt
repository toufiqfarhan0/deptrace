sam: Quick follow-up to the hosting RFC: propose a tiny "discover" probe so Private can run sidecarless by default. Probe on first route, cache per-tenant (5m), and have a compat adapter fallback for legacy installs.

rachel: Sounds reasonable. Major worry is adding latency on first request. What are our budgets?

sam: First-request only during rollout for a tenant. Target: <10ms on warm connections, we'll async-warm for tenants used regularly. Cache TTL default 5m; runtime can specify cap_ttl_seconds (min 60, max 3600).

nikhil: Security: controlplane must never hold unwrapped keys. Runtime should return an attestation token over mTLS; controlplane validates attest but never receives raw key material.

sam: Exactly. Auth flow: controlplane validates client token, probes runtime /_redwood/discover, gets manifest with auth_chain hint (e.g., "attestation+mTLS").

rachel: How do we handle older Private installs with no probe endpoint?

sam: Fallback to compat adapter that emulates the sidecar protocol. Mark tenant as "legacy_compat" in cache and surface a console notice. Emit metric compat_fallback_count.

nikhil: Add audit event when we create a compat mapping (tenant, reason, deploy id). Also add webhook support so runtime can signal manifest changes to invalidate cache immediately.

sam: Good call. Minimal probe shape we'll ask runtime implementers to expose: 
POST /_redwood/discover -> {"tenant_id":"acme","capabilities":["kvcache","batching"],"auth_chain":"attestation+mTLS","preferred_model_variants":["q4_0","q8_0"],"cap_ttl_seconds":300}
