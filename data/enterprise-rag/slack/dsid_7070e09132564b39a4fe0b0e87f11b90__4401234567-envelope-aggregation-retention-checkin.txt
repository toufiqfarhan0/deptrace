maya: quick follow-up to the RFC: i'm calling the pattern 'envelope aggregation' instead of microcredit to emphasize grouping and lifecycle. want ops + billing thoughts before i write the addendum.

oliver: naming nit aside, what's the core invariants we need to guarantee for billing correctness?

maya: three invariants: 1) no double-charge (dedupe across retries), 2) attributable to a single external request (envelope as the tie), 3) provable lineage for audits.

toni: for (1) we need a dedupe key that survives retries & restarts. microcredit_id + adapter_instance should do it. if adapters can generate stable uuids we good.

lee: also need a commit handshake. adapters should POST microcredits to ingest and await a commit ack (idempotent). ingest returns status {ok, duplicate, rejected}. adapters retry until ok/duplicate.

sam: what about partial fanout where one adapter succeeds and another times out but later retries and replays? how do we present to customers?

maya: UI/UX: provisional invoice shows committed envelope totals with tag `provisional:true`. after compaction window we mark `final:true` and send event. we must document the reconciliation window and potential delta.

oliver: how long is the reconciliation window? that impacts customers.

maya: default 48h for hosted, but per-tenant override to 7d/90d for enterprise auditors. infra: can we plug that into retention + finalization TTL?

infra-bot: ticket suggestion: INF-8102 retention-ttl-per-tenant + billing-finalize-ttl knobs.

lee: operationally we will have a huge number of microcredit rows for chat chains and routing. batching ingestion is must. adapters should be able to POST arrays of microcredits. also consider sidecar aggregation that buffers per-envelope for 100ms and flushes in bulk.

toni: buffering introduces a durability vs latency tradeoff. if sidecar crashes, we need replay support. prefer adapters do batching as primary, sidecar optional.

sam: audit proofs: compact ledger rows should include `raw_digest` (sha256 of concatenated raw microcredit ids) and `sample_ids` (list of a few raw microcredit_ids). when a dispute occurs, we can present sampled raw rows and the digest to show they match the compacted aggregate.

maya: agreed. addition: include `compaction_timestamp` and `compactor_version` so we can show which algorithm produced the digest.

oliver: index design: envelope_id index helps lookups but can become hot for heavy tenants. propose sharded envelope index: envelope_id_prefix -> shard. also TTL-partitioned tables for raw microcredits.

lee: storage flow sketch: raw_table (ingest, short TTL), compact_table (append-only aggregates, long retention), and final_ledger (cryptographically signed monthly snapshots for billing).

sam: signing final_ledger is key for legal defensibility. HSM/KMS sign the snapshot; store signature alongside snapshot_id.

maya: handshake pseudocode we can include in addendum. quick version here:
```
POST /ingest/microcredits
body: [{envelope_id, microcredit_id, tenant_id, tokens, model, attempt_id, status}]
response: [{microcredit_id, result: ok|duplicate|error, seen_at}]

Ingest dedupe by microcredit_id (unique index). if duplicate -> return duplicate. if new -> append to raw_table and emit pubsub event for compactor.
```

toni: can we support adapters that only know tenant-level id and not envelope_id (legacy adapters)? need compatibility mode where ingest assigns envelope_id and returns it.

maya: yes: ingest can mint envelope_id when missing and return it. but prefer adapters propagate envelope_id to preserve traceability. compatibility mode should be marked in headers for auditing.

oliver: observability: require trace id on envelope and span links from adapters. add lightweight envelope metrics: tokens_per_envelope, microcredits_per_envelope, commit_latency_p50/p95.

lee: alerts: sudden jump in `uncommitted_envelopes` or `inflight_microcredit_retries` should page oncall. also watch compaction backlog.

sam: query/forensics: need one-click for ops to fetch raw microcredits by envelope_id and to view their attempt history. don't rely solely on compact_table for investigations.

maya: we'll add an ops-only readonly index with faster lookups and ensure RBAC hides raw rows from non-admins.
