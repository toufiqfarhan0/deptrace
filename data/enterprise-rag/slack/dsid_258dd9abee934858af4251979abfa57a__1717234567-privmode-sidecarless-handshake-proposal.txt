anna: Quick follow-up from the RFC — proposing a small, pragmatic refactor to the hosting handshake so Private mode can operate sidecarless by default while keeping a clear auth and capability negotiation path. TL;DR: capability-discovery + explicit auth-chain, with a compatibility shim for older Private deployments.

mike: Can you sketch the handshake flow? I'm worried about trying to detect capabilities at request time and adding latency.

anna: Sure — flow is minimal: client -> controlplane (verify token) -> capability discovery probe -> route to runtime. Discovery returns a small capability manifest and auth_chain hint. Cache per-tenant for 5m to avoid per-request probes.

jess: :thinking_face: Where does KMS/HSM key access live in sidecarless? We need to avoid controlplane holding unwrapped keys.

anna: Good point. Plan is: runtime (customer-managed) holds key material. Controlplane gets an attestation token from runtime via mTLS; attestation references key policy. We never transmit raw keys.

mike: How do we fallback to sidecar mode if the runtime doesn't support discovery? We have many existing Private installs that won't update immediately.

anna: Compatibility shim: if discovery fails or manifest flags missing, route to a compatibility adapter that speaks the old sidecar protocol. That adapter provides a lightweight translation layer. Mark tenant as "compat-legacy" in our cache and surface a console warning.

diego: Operationally: we need metrics for discovery latency, failure rates, and compat fallthroughs. Also a circuit breaker — if discovery errors spike, we should auto-switch tenants to compat mode for the remainder of the SLO window.

jess: Agree on metrics. Also add an audit event whenever we create a compat mapping (who/when/why). Security will want retention.

anna: Added to the plan. Also thinking about an opt-in feature flag per-tenant: `private_handshake=v2` so early adopters can exercise the new path.

mike: Can you show the minimal config snippet we'd push for runtime implementers?

anna: Yep — proposed probe and response shape below (very small):

```

{"version":"1","capabilities":["kvcache","inference_v2"],"auth_chain":"attestation+mTLS"}

# example runtime manifest response
{"tenant_id":"acme","supports_batching":true,"max_seq_len":2048,"auth_chain":"attestation+mTLS"}
```
