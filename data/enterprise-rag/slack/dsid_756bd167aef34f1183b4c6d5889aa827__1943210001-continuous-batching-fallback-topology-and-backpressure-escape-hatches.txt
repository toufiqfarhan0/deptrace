samir: implementation notes:
- offer returns { decision, lease_ttl, headroom_hint }
- lease_ttl prevents lease-holding forever when caller stalls
- headroom_hint is a numeric token for backlog severity (0..100)

michael: can we avoid RTTs for offer/commit on hot paths? we should allow a synchronous inproc fastpath where the scheduler is colocated.

ashley: yes. adapter should be polymorphic: inproc impl is zero-copy sync; rpc impl uses the same semantics over gRPC. keep semantics identical but allow optimized codegen for local path.

lee: backpressure signal: rather than a binary busy flag, streaming clients want a gradient. suggest 3 signals: GREEN (no wait), AMBER (queueing likely, give headroom), RED (reject -> fallback). Can we map to HTTP 202 with Retry-After for AMBER?

samir: mapping to HTTP works. also emit a small json field: { admission: "amber", headroom_ms: 40 } so SDKs can adapt without hardcoding "Retry-After" heuristics.

ashley: edge-case: a request gets AMBER, then sits until lease_ttl expires and is rejected. SDKs should be able to extend the lease via a keepalive ping. We should document keepalive semantics.

olivia: from product pov, keepalive should be opt-in. default SDK behavior: if amber -> show spinner + optional retry. keepalive reserved for transactional workloads.

michael: observability: we need new counters and histograms: offer_latency, offer_decision, lease_expiry_count, fallback_count_by_reason, epoch_mismatch_count. Tag by tenant and model_variant.

samir: quick pseudocode for adapter interface:
```
interface BatchingAdapter {
  offer(req_meta) -> OfferResult  // sync or async
  commit(offer_id, payload) -> CommitAck

}
```
OfferResult = { decision: "accept"|"amber"|"reject", offer_id?: string, lease_ttl_ms?: int, headroom_hint?: int }
