elaine: Quick q — does the audit log export include IPs and user-agent? Also who is allowed to run exports for data older than 90d? Need to answer compliance reviewer today.

michael: Yep — schema has actor_id, actor_email, ip, user_agent, resource, action, outcome, and metadata like request_id.

ashley: Permissions: only members of the `audit-admins` group can kick off exports that include >90d hot logs. For ad-hoc >90d exports we require a SecOps approval (submit via /approvals or tag #eng-security).

security-bot: :warning: Reminder: Exports that may contain PII are redacted by default. Redaction modes: `mask` (xxx@****), `hash` (sha256), or `none` if you have approved justification. See https://internal.redwood/sops/audit-redaction-policy

jordan: S3/export format details: we stream newline-delimited JSON (ndjson), gzipped. Each record is a single event object. Example request (CLI):

```
curl -H "Authorization: Bearer $TOKEN" \
  -X POST https://api.redwood.com/audit/v1/exports \
  -d '{"start":"2025-08-01T00:00:00Z","end":"2025-09-01T00:00:00Z","format":"ndjson","redact":"mask","destination":{"type":"s3","bucket":"log-archive","prefix":"exports/"}}'
```

michael: Export response includes job_id. Once job completes we post a signed s3 URL to the requestor and SecOps. Links expire after 72h. Export metadata also contains `exporter`, `requested_at`, `approved_by`, and a sha256 checksum for integrity.

sre-oncall: Note on retention: default hot retention is 90d. We automatically move archives to `log-archive` for teams that opt in; long-term storage is cheaper but query latency higher. We do not keep full-fidelity events beyond 1yr unless the project has a retention contract.

ashley: Process for sensitive exports: open ticket in #eng-security with justification, include timeframe and recipient. We run a quick redaction check and either approve or require masked/hash. SecOps will attach approval token to the export job.
