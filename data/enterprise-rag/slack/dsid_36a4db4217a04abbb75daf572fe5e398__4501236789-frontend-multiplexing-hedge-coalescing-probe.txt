sam: Quick question — hedging + multiplexing probe. If we coalesce hedged requests at the edge, do we preserve per-substream idempotency tokens? Trying to avoid duplicate side-effects when we dedupe/fan-in.
jia: Short answer: not for free. If we merge requests we either (a) keep per-subrequest metadata all the way to the service, or (b) accept that only idempotent reads are safe. Both have tradeoffs.
matt: Option (a) seems heavy — doubles header surface area and tracing. Could we instead gate hedging so coalescing only happens for read-only routes (embeddings, search)? That keeps writes simple.
irene: For streaming we also need a checkpointing model. If we coalesce midstream, we must record KV-cache offsets per logical request. Otherwise resume/retry semantics get hairy.
sam: Sketch I tried locally:

```json
{ "hedge": {
  "enabled": true,
  "mode": "coalesce",
  "coalesce_window_ms": 8,
  "per_subrequest_id": "X-Sub-Id",
  "allow_side_effects": false
}}
```

sam: With that, edge attaches X-Sub-Id to each substream and keeps a small in-memory map during the coalesce_window. If upstream accepts a single merged request, edge fans responses back to each sub-id. Works for small windows but memory grows with burstiness.
jia: Two operational concerns: (1) memory bloat on bursts, (2) billing/observability — are we going to attribute token counts per sub-id? Need accounting hooks.
matt: On (2) we can attribute by proportional split based on prompt lengths. Ugly but deterministic. Or require upstream to return per-subrequest accounting when it accepts a merged call.
irene: Another failure mode: upstream midstream aborts after partial tokens. We need an idempotent checkpoint so clients can resume from a token index. That implies we must propagate KV cache checkpoints as part of X-Sub-Id state.
sam: TL;DR proposals:
- Restrict coalescing to read-only routes by default (:thumbsup: safe).
- Add optional per-subrequest metadata headers for teams that want to opt-in.
- Instrument a coalesce QPS gauge and per-window mem usage; auto-fall back to non-coalesced when > threshold.
matt: Agree. Also add P95 gating so we only hedge when p95 upstream latency > N ms. Saves churn.
jia: Small nit: implement metrics as counters+histograms so we can test synthetic workloads (no blind toggles).
