Open to wording suggestions — want small and scannable.

aisha: For accessibility nits: color palette currently uses purple/green which are close for some deuteranopes. Suggest we use ColorBrewer 2 (blue/orange pair) and add hatching pattern for offline mode.

sam: +1 for hatching. Also, the hover tooltip is too dense — we should show only the 3 most actionable items: name, p95, and link to traces. Everything else can live in the expanded panel.

jon: On annotations: users want to attach a saved run or alert snapshot. UX idea: inline little pills under a bar with tiny timestamp and icon -> clicking opens a side panel with details. Keyboard: focus cycles into pills with `ArrowRight/Left` and `Enter` opens.

maya: That fits with our Console patterns for small chips. How about copy for the pill? short format `2026-02-03 • deploy #128` or `+ jazz-optimizer`?

lee: Prefer `YYYY-MM-DD • deploy #` as canonical; include optional tag after a dash for short context. So `2026-02-03 • deploy #128 — jazz-optimizer` (screen readers: read the whole pill text).

aisha: Microcopy for time-range picker: current label says `Last 1h`, but people were confused whether that's rolling or wall-clock aligned. Maybe change to `Last 1h (rolling)` and introduce an advanced menu with `Snap to: [wall-clock | rolling]`.

sam: Hmm I'd rather not add parenthetical everywhere. Could we show the picker hint on hover: `Rolling window: recent 60 minutes`? Keep the label compact.

maya: Good alternative. We'll add an info icon with tooltip copy: `Rolling windows slide with time; wall-clock snaps to fixed boundaries`.

jon: Performance note: the waterfall has many bars for high-cardinality queries; we should show a sampling control at the top to switch between `Top 10`, `Top 50`, and `All (sampled)` with estimated sample rate shown. That avoids overplotting.

aisha: For the sampling control microcopy: `Showing top N segments by throughput. Lower N reduces rendering cost.` Keep it short. Also add a small live-estimate `~12ms/frame` to warn when rendering cost is high.

maya: Nice. UX probe: If user selects `All (sampled)`, we should show a subtle banner `Rendering sample: 25% of segments — results approximate` with a `Why?` link that opens a short explainer.

lee: Accessibility: ensure that the dark banner has sufficient contrast and that the `x` close button is reachable via keyboard.

sam: Visual tweak: when a bar is focused, we currently overlay a blue halo and keep the rest dimmed. For colorblind users that dimming reduces context. Can we instead use an inset border and slightly increase brightness of the focused bar?

aisha: Also add a preference toggle `Reduce motion` and `High contrast` that maps to alternative renderings (no dimming, thicker focus border).
