jin: That smells like our kernel-key misspec. torch.compile seems to fold the leading dynamic dim into a traced constant shape when graph capture happens, so the autotuner key differs from runtime shape bucket. We saw similar with kv-cache priming but not exactly this case.

maria: Do you mean the compile-time shape key isn't including "seq_bucket" so it falls back to a safer generic kernel?

jin: Exactly. compile produces a graph key like (bs=1, hidden=4096, seq=-1) -> translated to internal capture shape 512, whereas our autotuner expects normalized seq buckets (256/384/512). Kernel selection code uses the graph hash + arch which misses the bucket.

ara: I pushed a quick patch in a local branch that forces kernel_key = (arch, seq_bucket, batch_mod) during compile-handshake. Ran short microbench: p99 down 12%, throughput +8% for seqlen 512. Patch:```
# handshake override
def select_kernel_key(meta):
    seq_bucket = bucketize(meta.seq_len)
    return (meta.arch, seq_bucket, meta.batch%8)
```
