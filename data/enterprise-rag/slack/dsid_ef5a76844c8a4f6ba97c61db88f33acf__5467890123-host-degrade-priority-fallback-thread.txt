Priya: I like the idea. High-level: instead of everyone hard-migrating, let lower-priority routes run in degraded_host_mode where we stream host pages and enforce a tenant credit cap so host bandwidth is shared fairly.

Samir: Two implementation pieces: (1) admission control/credits per-tenant, (2) tiny pinned window (N pages) per sequence to avoid reloading same pages repeatedly. Credits should be configurable by route/tenant tier.

Nina: We should surface an abstract customer config:

degraded_host: { max_stream_bytes: 1MB, credit_ms_per_minute: 2000 }

Keep public API simple; map to credit/pin details internally.

Alex: Telemetry must include fallback_mode, host_stream_bytes, credit_used, and backpressure_events. Also add a per-tenant backlog gauge so Console can show which tenants are throttled.

Priya: For fairness I propose a weighted leaky-bucket: each tenant has weight w; host stream grant = base_rate * w. That naturally gives higher-tier tenants more headroom.

Kai: micro-impl notes: host-stream fast-path should use async scatter-gather reads, lock-free buffers, and a per-sequence small LRU of pinned pages. If credit depleted, we either queue the request briefly (<=10ms) or escalate to a hard migrate if route is low-latency.

Samir: Need to decide queue semantics: FIFO vs priority. For fairness, queue by tenant weight adjusted deadline. Also add a global backpressure metric that triggers short-canary denial under pathological storms.

Maggie: Security note: host staging must be zeroed before reuse and per-tenant meta must be cryptographically scoped. Add KMS/HSM item.
