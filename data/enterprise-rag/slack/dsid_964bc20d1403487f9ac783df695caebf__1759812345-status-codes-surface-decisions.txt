chris: I like keeping it small. Two asks: (1) include `retry_after` in 429/503 responses when possible, (2) machine-friendly `code` field so SDKs can switch behavior. e.g.:

```json
{
  "error": {
    "code": "RATE_LIMIT_EXCEEDED",
    "status": 429,
    "message": "Token rate limit exceeded",
    "retry_after": 4
  }
}
```

meera: For validation, let's be explicit: 400 = syntactic (bad JSON, missing required top-level fields), 422 = semantic (prompt too long for model profile, incompatible schema for structured output). SDKs should surface 422 as non-retriable by default but allow opt-in heuristics.

paul: On model-unavailable: prefer 503 + `code: MODEL_UNAVAILABLE` and include `fallback_model` when automatic fallback applied, e.g.:

```json
{
  "error": {
    "code": "MODEL_UNAVAILABLE",
    "status": 503,
    "message": "Requested model currently overloaded in region",
    "retry_after": 12,
    "fallback_model": "redwood/gpt-lite-1"
  }
}
```

maya: Important product constraint: enterprise customers want deterministic semantics.
