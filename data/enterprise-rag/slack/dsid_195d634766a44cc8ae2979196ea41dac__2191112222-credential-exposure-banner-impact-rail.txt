Sam (product): Quick run-through: propose a warning-banner pattern for credentials that are shared across org boundaries or have broad scopes. Goal: make risk visible before actions (rotate/revoke/transfer).
Ria (design): Sketch: sticky banner at top of credential detail when scope >= org-wide or external team mapping exists. Banner CTA: 'View impact' -> opens a right rail with affected services + list of teams. Keep banner subtle but persistent until dismissed.
Ben (backend): We can compute exposure_score server-side and return exposures: {count, examples, sensitive_flags}. Endpoint: GET /v1/keys/:id/exposure. Make sure it's cached for 1min to avoid heavy scans.
Sam (product): UX questions: should the banner block destructive actions until acknowledged? I think block only for transfer/hard revoke; rotate should be allowed but with extra confirmation.
Iris (content): Suggested copy: Banner text = "This credential grants access to X teams and Y services. Rotating or transferring may impact integrations." CTA = "View impact". Confirm modal header for hard revoke = "Permanently revoke credential" with helper: "This will break integrations immediately".
Ally (a11y): Banner must be keyboard-focusable and dismissible. 'View impact' should open a panel with role=dialog and aria-modal=true. Exposed services list needs aria-labels and grouping. If we block an action, announce with aria-live polite. Also ensure color contrast of banner icon meets 4.5:1.
Ben (backend): Edge-case: if exposure calculation is stale, show warning tag: "Exposure estimate: may be incomplete" and surface last_scan_ts. If scan is still running, UI should show spinner and let user decide whether to wait.
Ria (design): For the impact rail: show three tabs: Services, Teams, Policies. Each row has quick actions: 'Contact owner', 'Attempt auto-update', 'Mark as unaffected'. For mobile, collapse to a single list with badges.
Sam (product): Permissions: only users with key.manage or admin can dismiss banner permanently. Others can snooze for 24h. Dismiss should create audit event.
Iris (content): Dismiss confirmation copy: "Mark as acknowledged for this key? This will be recorded in the audit log." Dismiss CTA labels: 'Acknowledge' / 'Cancel'.
Ally (a11y): Confirm input for hard revoke should require typing the key name; provide clear accessible instructions and live error message if mismatch. For the 'mark as unaffected' action, ensure we expose a reason dropdown with accessible labels.
Ben (backend): Audit events: key.exposure.acknowledge, key.action.blocked, key.impact.scan_started. For blocked attempts we return 403 with reason 'exposure:risky' and include remediation hints.
policy-bot: Policy check: org policy 'external-key-transfer' = disallow -> any transfer attempt returns 409 and suggests request flow -> /orgs/:id/requests.
