owen: Agreed on KV impact — streaming tends to create more partial prefixes per client, so effective KV reuse is lower. If kernel expects high KV locality it may thrash. We saw similar behaviour in q4 when sequence distribution changed.

jake: That delta is telling. Kernel selection should consider an estimate of KV reuse (or 'streamingness') not just mb_size. Current heuristic is basically: if mb*avg_seq > 1024 -> pick optim kernel. Clearly not sufficient.

sylvie: Proposal: augment selection with a small online estimator: per-worker exponentially-weighted KV-hit-rate (EWMA). If EWMA_kv_hit < 0.8, route to fallback kernel optimized for low-KV locality even if mb*seq is large.
