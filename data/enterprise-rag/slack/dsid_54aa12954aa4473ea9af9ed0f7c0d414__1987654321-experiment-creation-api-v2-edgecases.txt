sam: runtime note — if we enforce p95 latency guard in routing path, we need fast per-variant sliding windows. current KV cache hits make this possible but we must avoid per-request cross-shard locks. can we expose the guard check as async signal too (route then retract) or would that break safety?

arjun: I think guards must be synchronous for hard limits (e.g., reject requests when variant is unhealthy). soft guards can be async with automatic weight adjustments. implementation: local counters per-host + periodic cross-host sync. if a host detects variant breach, it should stop routing to that variant and return 409 with body containing guard metadata. example error payload:
```json
{ "error": "guard_triggered", "variant": "B", "guard": "max_error_rate", "observed": 0.028, "window_sec": 60 }
```
