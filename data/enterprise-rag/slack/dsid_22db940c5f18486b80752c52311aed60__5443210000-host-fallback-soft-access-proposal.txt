Samir: What if we avoid blocking the entire request? A "soft" fallback could let the sequence proceed using host streams and degrade per-token latency instead of stalling the pipeline. Might be fine for lower-SLO routes.

Nina: Proposed user-facing modes (route-level, default=hard_migrate):
- hard_migrate: preserve per-token latency by migrating pages to GPU (higher bandwidth/cost)
- soft_access: keep pages on host, stream reads, allow degraded token latency but reduce impact on other tenants

Kai: Implementation-wise soft_access needs: residency hints per allocation, a fast non-blocking host-stream path, and a small pinned window for in-flight sequences to avoid repeated churn.

Maggie: Draft of minimal route API (we should keep it small):
```

```
