Eng-Infra-Arun: That smell like header reassembly/mangling across a TCP proxy chain. NLB in TCP mode + proxy-protocol + an intermediate NAT can cause the client to open a TCP connection that gets reused and upstream proxies to re-emit headers. Eng-Platform-Priya: Repro hypothesis: client sends Authorization once, haproxy in front normalizes and forwards, NLB in TCP mode with proxy-protocol hands off to our internal NAT, on connection reuse haproxy forwards an extra empty header (maybe due to a bug in header concatenation when switching from HTTP/1.1 chunked/keepalive). Eng-SRE-Joe: Two corrective actions to test: 1) ask customer to set NLB to TLS termination (ALB) or switch to ALB/HTTP mode temporarily to see if behavior stops; 2) add a temporary Envoy header sanitizer at edge to collapse multiple Authorization headers, prefer non-empty. Eng-SRE-Joe: Config snippet to drop empty auth headers (experimental):
```
# envoy Lua filter pseudo config
inline_code: |
  function envoy_on_request(request_handle)
    local h = request_handle:headers():get('authorization')
    if type(h) == 'table' then
      -- keep the first non-empty value
      for i,v in ipairs(h) do
        if v and v ~= '' then
          request_handle:headers():replace('authorization', v)
          return
        end
      end
      request_handle:headers():remove('authorization')
    end
  end
```
(This is a quick workaround while we root-cause upstream.)
