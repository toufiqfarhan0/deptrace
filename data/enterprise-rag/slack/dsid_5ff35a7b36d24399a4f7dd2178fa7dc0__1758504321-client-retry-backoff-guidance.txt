Tomas (SDK): SHORT GUIDANCE for customers to mitigate impact from our side: 
- Reduce client retry counts: set max_retries=3 for idempotent calls (embeddings, rerank). For generative non-idempotent calls, max_retries=0 or rely only on server Retry-After.
- Use jittered exponential backoff: base=500ms, factor=2, jitter=uniform(0, base), cap=20s. Example pseudocode: 
```
wait = min(cap, base * 2**attempt) + random(0, base)
```
- Honor server signals: if response includes `Retry-After` header or `X-RateLimit-Reset`, back off until indicated. Do not hammer.
- Add `Idempotency-Key` header for requests that can be retried safely; make it a UUID v4.
- Prefer conditional retries: only retry on network errors and 429/503, avoid retrying on 4xx client errors other than 429.

Tomas (SDK): Python snippet customers can drop in quickly: 
```python
import time, random, uuid

def backoff_sleep(attempt, base=0.5, cap=20.0):
    sleep = min(cap, base * (2 ** attempt))
    sleep = sleep + random.uniform(0, base)
    time.sleep(sleep)

headers = {"Idempotency-Key": str(uuid.uuid4()), "Authorization": "Bearer <REDACTED>"}
for attempt in range(4):
    resp = client.generate(..., headers=headers)
    if resp.status_code == 200:
        break
    if resp.status_code in (429, 503) or resp.is_network_error():
        if attempt == 3:
            raise RuntimeError('exhausted retries')
        backoff_sleep(attempt)
    else:
        # do not retry other 4xx/5xx
        break
```
