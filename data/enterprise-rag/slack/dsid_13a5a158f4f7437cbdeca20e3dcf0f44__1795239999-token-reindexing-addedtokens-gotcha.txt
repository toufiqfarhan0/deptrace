jeff: classic added_tokens gotcha. If `added_tokens.json` only lists strings, some conversion paths call `tokenizer.add_tokens([...])` and that assigns new ids at the end (or reindexes), depending on the tokenizer backend. Also watch out for fast vs slow tokenizers (`use_fast=True` vs python).

maria: diagnostics to run locally before conversion:```
python - <<'PY'
from transformers import AutoTokenizer
t = AutoTokenizer.from_pretrained('./hf_copy', use_fast=True)
print('vocab_size', t.vocab_size)
print('special_tokens_map', t.special_tokens_map)
print('added_tokens', getattr(t, 'added_tokens_encoder', 'N/A'))
print('ids for special', {k: t.convert_tokens_to_ids([v]) for k,v in t.special_tokens_map.items()})
PY
```
That ensures you capture HF-side token->id mapping to compare post-conversion.
