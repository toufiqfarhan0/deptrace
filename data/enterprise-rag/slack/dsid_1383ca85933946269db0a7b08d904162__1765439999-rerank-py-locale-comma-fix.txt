alex_eng: reproduced here. root cause: the python helper was joining scores with str(s) into a template string. on de_DE locales str(float) uses comma as decimal sep. then we end up with quoted strings in the final JSON. JSON numbers must use dot and not be quoted.

mike_ml: yep, that explains both the 400 (parser unhappy) and the odd ordering when backend coerces strings to numbers inconsistently.

sara_support: next steps? we need an actionable fix and a workaround for affected customers.
alex_eng: opened GH issue and PR: https://github.com/redwood-inference/sdk-python/issues/1432 and PR https://github.com/redwood-inference/sdk-python/pull/1450
- cause: locale-aware float->str in one path that built JSON with string templating
- fix: use json.dumps for arrays and ensure numbers serialized as numbers; add unit tests that run with de_DE locale
- CI: add a matrix entry to run tests with non-C locales

deploy-bot: canary build created for branch fix/locale-rerank-1450 — tag sdk-python-canary-1450

alex_eng: short-term workaround for customers: set LC_NUMERIC=C in the process environment or call locale.setlocale(locale.LC_NUMERIC, 'C') at startup. sample:
```
import os
os.environ.setdefault('LC_NUMERIC', 'C')
# or
import locale
locale.setlocale(locale.LC_NUMERIC, 'C')
```
