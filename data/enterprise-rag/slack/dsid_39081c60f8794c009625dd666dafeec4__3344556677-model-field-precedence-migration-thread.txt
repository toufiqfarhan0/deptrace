maya: Heads-up from manual QA: a weird edge case in a few v2 docs where we show both "model" and "model_id" in examples. That confuses readers and the shim can pick the wrong variant. Repro below.

frank: can you paste the minimal repro?

maya: POST /v2/invoke with body `{"model":"redwood-13b","model_id":"redwood-13b-gpu","input":"Hi"}` -> shim prefers model_id in some client helpers, but server alias resolver sees 'redwood-13b' and resolves to quant variant. Result: inconsistent serving.

anya: wow. docs should recommend a single canonical field and explain precedence. Also we should show a Ruby SDK snippet (we're missing many non-js examples).

maya: agreed. Proposal: add short section "Field precedence and safe migration" under /docs/migration/v2 with: 1) canonicalize to model_id, 2) examples for curl/py/js/ruby, 3) how to opt-in to strict behaviour via header `X-RW-Strict: true`.

sam: I'll open a small PR to replace mixed-field examples and add the Ruby snippet. Branch docs/migration/canonical-model-field.

sam: Ruby snippet (inline):
```ruby
require 'net/http'
uri = URI('https://api.redwood.com/v2/invoke')
req = Net::HTTP::Post.new(uri)
req['Authorization'] = "Bearer #{ENV['RW_TOKEN']}"
req['Content-Type'] = 'application/json'
req.body = { model_id: 'redwood-13b', input: 'Summarize...' }.to_json
res = Net::HTTP.start(uri.hostname, uri.port, use_ssl: true) { |http| http.request(req) }
puts res.body
```
