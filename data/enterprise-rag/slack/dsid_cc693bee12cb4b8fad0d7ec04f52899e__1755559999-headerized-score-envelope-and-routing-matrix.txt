maria (Eng Platform): Quick proposal: switch /rerank to a headerized score envelope so we can attach routing/telemetry metadata without changing candidate list shape. Draft envelope: 
```
{
  "scores": [0.92, 0.41, ...],
  "headers": {
    "model_affinity": "reorder-v2",
    "units": 3,
    "precision": "int8"
  }
}
```
Thoughts?

aj (Eng Runtime): I like separating meta from scores. Main concerns: SDK compatibility + how runtime charges quotas. Backwards compat: if caller omits envelope we should accept old array shape.

ben (Product): +1 on compatibility. Suggest we version the envelope via a header rather than body field so we can route by Accept/Content-Type: `application/vnd.redwood.rerank.v2+json`. UX in docs will be clearer.

sara (SRE): For quotas we need deterministic unit accounting. Should `units` be explicit or inferred? Explicit is clearer but users might forget. If inferred, we need consistent rules across model variants.

kai (Console): Console needs to surface the routing matrix using those headers. If `model_affinity` is present, show expected fallback chain and estimated cost/latency for each variant. Admins should be able to preview the routing decision for a given envelope.

maria (Eng Platform): Edge cases: when runtime falls back to a cheaper variant, preserve headers but add `fallback_reason` and `effective_model`. Also expose `charged_units` in response metadata so callers can reconcile billing.

aj (Eng Runtime): Telemetry: add `score_encoding` and `model_variant` tags to traces. Also ensure no user PII can flow into headers. We'll sanitize header values in the runtime.

ben (Product): For rollouts, we can canary by envelope version + model_affinity weight. Console needs a simple toggle to route X% to `reorder-v2` and the rest to `reorder-v1`, with per-tenant overrides.

sara (SRE): Implementation note: batching changes accounting — unit counts need to sum across batched requests. Also KV-cache hits should reduce charged units; runtime must report raw tokens vs charged units.

kai (Console): Mockup idea: show a small matrix row per tenant: `model_affinity | envelope_version | units | avg_latency | p95_cost | rollout% | last_deployed`. Allow admins to simulate an envelope and see the routing path.

maria (Eng Platform): One policy decision: do we keep per-request rate limits or switch to per-unit quotas? Proposal: enforce both. Requests still limited (protect control plane), but billing/soft-quota is per `units`. If units missing, default to 1.
