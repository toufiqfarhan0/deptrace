kevin: Hmm we moved some deployments to emit either response-header cursors (`X-Pagination-Cursor`) or body meta (`meta.next_cursor`) depending on ingress. Go SDK only checks `resp.Body.NextCursor` so header-only cases are treated as end-of-stream.

rosa: Also saw that hosted infra sometimes signals credential rotation with `X-Ephemeral-Rotate: 1` while some private stacks use `X-Auth-Refresh: true`. SDK middleware only watches for `X-Auth-Refresh`. When header mismatch happens, SDK never rotates ephemeral creds.

ojules: So two incompatibilities: pagination cursor location (header vs body) and auth-rotation header name drift. Both cause long-running pagers to break then surface as 401s.
